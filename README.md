# DeepFish v0.25.3（web-fishing-game）

零第三方依赖的多人联机网页钓鱼小游戏。**所有处理逻辑在服务端**：钓鱼循环、掷骰、词缀加成、
资产结算、钓竿配置均由后端权威执行，前端只发指令、收 SSE 广播、渲染。纯原生 Web 前端 +
Go HTTP 后端，游戏数值目录由 Go catalog 和前端快照共同维护；桌面与手机端各自排版，全站像素页游风格。

| 特性 | 说明 |
|---|---|
| 运行时 | 游戏服务使用 Go + PostgreSQL；浏览器端无需 `npm install` |
| 服务器权威 | 客户端无法伪造渔获与资产，前端不持账本 |
| 实时联机 | SSE 广播：在线玩家、渔场人数、渔获动态、行情、交易、横幅 |
| 数据存储 | PostgreSQL 统一保存身份、资产、玩法、交易、Wiki 与审计数据 |
| 可运营 | 管理后台分区管理游戏与 Wiki，配置保存即生效并实时同步在线玩家 |
| 前端 12 个入口 | 钓鱼 / 渔屋（晒场 · 宠物 · 角色 · 钓竿） / 背包 / 工坊（装备成长 · 钓鱼套装） / 开箱 / 远洋 / 社交 / 商城（限购 · 收购 · 市集） / 图鉴（含记录） / 反馈 / 日志 / WIKI |
| 场景引擎 | 零依赖 Canvas 场景层：手绘像素底图 + 水面倒影实时演算 + 氛围粒子 + 指针视差，按渔场换色 |
| 基础设置 | 文字大小、清晰字体、场景动效、纪录播报与普通提示精简；浏览器本地保存，游戏进度不受影响 |

## 配套 Wiki

Wiki 显示名称为 `wiki`，由游戏服务器同域托管 `/wiki/`，包含钓场资料、玩法攻略、**配装模拟器与熔炼模拟器**；页面外壳与工坊模拟器复用游戏 UI。
详细范围、数据同步方案、计算规则和验收标准见 [Wiki 开发文档](docs/wiki/DEVELOPMENT.md)，进展见 [Wiki 规划与开发日志](docs/wiki/CHANGELOG.md)。可运行 `npm run wiki:sync`、`wiki:check`、`wiki:test`、`wiki:test:browser`、`wiki:build` 和 `wiki:verify:server` 执行版本同步与专项回归。正式 Wiki 的数据与公式必须来自正式服务端快照并与服务端共用规则实现，不能伪造或滞后。
Wiki 资料站、配装模拟器、熔炼模拟器、构建检查和本地验收已实现。官方攻略、更新记录与玩家投稿由 Go 服务写入 PostgreSQL；公开内容接口只下发攻略元数据，正文由 `/api/wiki/guides/<id>` 按需读取，列表分页/搜索走 `/api/wiki/guides`。用户投稿默认自动通过、提交后立即公开（作者可删除自己的自动通过投稿），设置 `WIKI_GUIDE_AUTO_APPROVE=0` 重启后恢复「提交 → 待审核 → 管理员审核」流程。首页与更新页默认只突出最近一次更新，完整版本演进可在历史入口展开。Release 包内置 `SOURCE_COMMIT.txt`，服务端也可用 `SOURCE_COMMIT` 环境变量显式注入完整提交 SHA。

## 快速开始

安全加固说明见 [SECURITY.md](SECURITY.md)：包含管理员 MFA、Cookie/HTTPS、9001 仅本机监听、注册配额与计算验证，以及市集分页/增量通知。市集 API 默认 30 条、最多 100 条，调用方需遍历分页。生产部署后必须复测公网 9001 不可达。

游戏服务现在只使用 Go 后端。运行前准备 PostgreSQL，设置 `FISHING_GO_DATABASE_URL`，并按
[server-go/README.md](server-go/README.md) 先执行数据库迁移和默认 catalog 发布。Node.js 仅用于 Wiki 构建、旧协议对照工具和前端开发静态服务器，不再启动游戏后端。

```bat
run.bat                 :: Go 集成模式：后端 9000，同时托管 frontend/
start-frontend.bat      :: 可选分离模式：前端静态服务器 5500（与 run.bat 并用）
Start-Game-HTTPS.bat    :: 已安装 HTTPS 服务时使用：Go 后端 9001，公网 HTTPS 9000
```

打开 <http://localhost:9000>（分离模式 <http://localhost:5500>），注册登录即可；
**多开浏览器标签 = 多真实玩家**。非 Windows 在仓库根执行 `npm start`（或在 `server-go` 目录执行 `FISHING_GO_FRONTEND_DIR=../frontend FISHING_GO_LISTEN=127.0.0.1:9000 go run ./cmd/game --role=all`）。前端也可托管到任意
静态服务器（`API_BASE=auto` 自动连同主机的 9000，或改 `frontend/js/config.js`）。

**Windows HTTPS 启动**：先运行独立 HTTPS 安装包的 `Install-HTTPS.bat`，完成 Caddy 和免费证书配置。
之后在每个游戏 Release 目录中双击 `Start-Game-HTTPS.bat`，访问 <https://ipv4.rinkore.com:9000>。
启动器调用**当前 Release 目录**的 `run.bat`，Go 后端使用 9001。数据库连接通过
`FISHING_GO_DATABASE_URL` 注入；Go 不会自动读取或迁移旧 JSON 存档。
Caddy 开机自动启动，游戏仍需手动启动；新版安装包使用 Cloudflare DNS-01 自动申请和续期证书，
无需开放公网 80/443，只需转发 TCP 9000。安装时输入仅限 `rinkore.com` 的 API Token，
权限为 `Zone → DNS → Edit` 和 `Zone → Zone → Read`；域名记录保持“仅 DNS”（灰云）。
HTTPS 启用后不要单独运行普通 `run.bat`，否则会与代理争用 9000。

**管理后台**：`admin.html`，使用已授权的账号密码和验证器动态验证码登录。公开登录不再自动授予管理员。
管理员 MFA 通过 `server-go/cmd/admin provision` 的 JSON 标准输入配置，具体步骤见
[server-go/README.md](server-go/README.md)。普通游戏登录的 token 不能访问管理 API。
详细升级和验证说明见 [SECURITY.md](SECURITY.md)。

| 环境变量 | 说明 |
|---|---|
| `FISHING_GO_DATABASE_URL` | 必填，Go 应用 PostgreSQL 连接串 |
| `FISHING_GO_LISTEN` | Go 监听地址，`run.bat` 默认 `127.0.0.1:9000`；HTTPS 默认 `127.0.0.1:9001` |
| `FISHING_GO_FRONTEND_DIR` | Go 静态前端目录，`run.bat` 默认仓库/发行包内的 `frontend` |
| `FISHING_GO_TIMEZONE` | 业务时区，生产建议显式设置 `Asia/Shanghai` |

## 玩家功能开关

管理员登录后台后进入「🔒 功能开关」，勾选表示开放，修改后点击「保存功能开关」。
支持 9 个侧栏页面 + 2 个页签页（钓竿、记录）及其下的独立操作：钓鱼、钓竿装备/槽位/管理/自动配装、
角色同伴/船型、玩家交易、组件订阅、宝匣合成/开启、熔炼/重铸、限购购买、出售/自动售出、市集上架/购买、
图鉴、记录、反馈提交/跳过冷却。
关闭主页面会覆盖子项，但保留子项设置；重新开放主页面不会重置单项锁定。
**页签页跟着主页面走**：关掉「角色」或「图鉴」，其下的「钓竿」「记录」页签一并不可用；
只想停用某一件操作（例如维护期禁止上鱼但保留换装）时，关对应的子项即可。
**允许管理员进入已关闭功能**（v0.16.0）：勾上后，带管理员身份的操作不再受这些开关限制（玩家端照常受限），
便于维护期自测；关掉即恢复「管理员也遵守开关」。
出售与市集等开关作用于所有操作入口（包括背包和弹窗）。配置保存在 config.json 的 features，默认全部开放。
保存后经 SSE 同步在线玩家，锁定中的页面显示提示，操作接口返回 423 / FEATURE_LOCKED。
锁定钓鱼会停止正在进行的钓鱼；锁定交易会取消未完成交易；锁定出售或自动售出会暂停已有自动售出规则。
停止钓鱼、取消交易、撤回挂单接口始终可用，共享只读数据仍可供其他页面显示。
角色外观和自动配装属于本地界面功能，交易/资产相关操作另外由服务端强制检查。

## 数据存储

Go 服务使用 PostgreSQL 持久化身份、资产、玩法状态、交易、Wiki 和审计数据。
数据库结构由 `server-go/cmd/migrate` 维护，应用启动只检查连接和 schema，不会自动读取、改写或迁移旧 Node JSON 存档。
正式切换前应单独完成离线存档核查、备份恢复和数据迁移演练；旧 JSON 仅作为迁移对照资料。

## 架构要点

**服务器权威**：Go 服务的 `POST /api/fishing/start|stop` 启停服务端的钓鱼定时器，每竿按抛竿间隔掷骰
（上钩走后台公式、渔获从钓点掉落池按权重抽取），入库 / 图鉴 / 纪录 / 全服动态全部在服务端完成后，
经 SSE 定向推送 `catch` 与权威 `assets`；客户端无法伪造渔获。会话：注册必填 QQ 号，登录签发 token，
同账号二次登录顶号（旧会话全部失效），落盘只存 token 的 SHA-256。出售 / 挂单 / 购买 / 交易 / 开箱 /
熔炼的掷骰与结算同样全在服务端。

**前端瘦客户端（分层）**：

```
config.js   API_BASE 配置（默认 auto：同源 → 同主机 9000）
data.js     游戏数据目录（UMD：前端挂 window.GameData，后端 require 同一份）
engine.js   客户端状态层：展示状态 + 指令发送（无游戏逻辑）
net.js      网络层：指令 API + SSE 广播接收 + 版本守卫
ui.js       页面渲染与交互（9 个侧栏入口 / 14 个页面视图，含钓竿·记录等页内页签 + 子窗口 + 横幅 + 日志）
admin.js    管理后台页面逻辑（16 个页签）
```

高频广播**就地更新**（钓鱼页按结构签名走 `patchFishingLive()`、工坊保留输入焦点、背包出售后不重排）；
Canvas 场景使用 `ResizeObserver` 按需读取尺寸，仅在缓冲尺寸或渔场改变时重建地形，缓存天空与水色渐变；
滚出可视区或页面隐藏时跳过绘图，节点移除后释放观察器。无观察器的旧浏览器保留尺寸检查兜底。
场景性能回归：`node tests/scene-performance.test.js`（需要 `playwright-core` 与 Chrome/Edge，已纳入 `run-all.js`）。
全站不使用浏览器原生 `confirm / prompt / alert`；`fetch` 统一 8 秒超时（GET 重试一次，写操作不重试）；
组件被熔炼 / 出售 / 交易消耗后自动清空界面上的悬空引用。移动端 `max-width: 640px` 单独排版
（底部标签栏 + 单栏内容 + 底部近全屏面板，表单字号 ≥16px 防 iOS 聚焦放大）。

**版本守卫与无感热更**：版本号唯一定义在 `frontend/js/data.js` 的 `VERSION`，三条路径发现变化后
带 `?v=&t=` 强制整页重载一次（`sessionStorage` 防死循环）：启动比对 `GET /api/version`、SSE 重连的
`init` 带回新版本号（最快）、5 分钟兜底轮询 + 标签页回到前台补一次。静态资源始终 `no-cache`；
项目根的 `update.bat` 拉取 GitHub 最新 Release 覆盖升级（存档在文档目录、不受影响）。

**健壮性兜底**：服务端是所有玩家的单点，未捕获异常会让进程直接退出（表现为所有人同一秒掉线）。
三道防线：请求体统一走 `bodyObj()`（只接受对象，`null` 与裸值按格式错误返回 400，覆盖全部 POST 端点）；
钓鱼循环与市集清扫的定时器套 `try/catch`（单轮抛错只记日志、下一竿照常）；注册
`uncaughtException` / `unhandledRejection` 记录堆栈后**保持存活**（宁可丢一次结算，不整服下线等重启）。
**连接自愈（v0.16.0）**：服务端每 25 秒同时发注释与真实 `ping` 心跳，客户端据此判断连接是否「假死」
（readyState 为 OPEN 却收不到任何数据）；回到前台 / 从 bfcache 恢复 / 网络恢复 / 窗口聚焦时都会探测并按需**强制重建 SSE**，
另有 10 秒一次的看门狗兜底 —— 修掉手机切后台、PC 长时间切走后「看着连着、其实已经掉线」的老问题。

## 玩法系统

**钓点与钓速**：世界地图含 3 个常驻钓场（静水湖 / 急流河 / 落日海湾，各 3 钓点）+ 霜月冰湖活动场
（锁定占位），另有「出海」航线预告页签；带增益的钓点金框 + ⚡ + 数值常驻可见，点击直达。
`抛竿间隔 = 基础间隔 ×(1 − 有效钓速/100) ×(1 − 钓点钓速增益/100)`，不低于最短间隔
（默认基础 3000ms / 最短 800ms / 有效钓速上限 80%，后台可调）；有效钓速 = 词缀 + 全服加成（受上限截断），
钓点钓速增益为最终乘算。**上钩率由后台公式决定**（递归下降解析、不用 eval，默认 `clamp(90 + skill, 0, 100)`），
钓点可单独覆盖上鱼率与间隔。**双钓**：叠加值 A → 单次追加概率 `A/(A+100)`、最多连判 3 条，
世界基础双钓率 B 合成为 `1 − (1−B)(1−P)`。**体型**按 roll 模型（线性 / 正态默认 / 偏态）在鱼种基准区间取值，
体型词缀按百分比放大 / 缩小且不设固定上限（最小保底 1cm）。

**重连自动续钓**：开始钓鱼 / 切换钓点即写入存档（`lastFishing`），断线、顶号、服务器重启都不丢；
重建 SSE 连接时服务端按原钓点续钓，并在 `init` 里带回**钓点与钓速明细**（前端直接写回展示状态）。
只有玩家主动收竿才清除，续钓前校验钓点存在与钓场开放状态。

**品质与组件**：品质只有四档 —— 普通 / 稀有 / 史诗 / 神话（渔获与组件共用命名与配色；「大鱼」是掉落
**档位**、不是品质；神话只能由宝匣产出）。组件 = 底材 + 品质 + 随机词条实例：29 种底材 × 6 类词缀
（钓速 / 技巧 / 稀有度 / 材料概率 / 体型 / 双钓概率），每条带底材专属数值区间并含正负取舍（负值红色显示）；
品质决定词条数的**自然上限**（品质上限 1/2/3/4，再被底材池长夹取）与基准价倍率（1/1.5/2.4/3.6）；
界面显示的「n/池长 词条」以**该底材的词缀池长**为分母：分子到达分母即「满词条」（金色 + 饱满的/完美的），
池外补出来的额外词条（工坊补缀 / 宝匣突破件）让分子超过分母，读作「越过词缀池边界」（突破）。
**实例身份 = 内容签名**
（`rod_bamboo#rare#spd+12,size-3`，词条按底材池顺序规范化），完全相同的组件天然堆叠。掉落档
`common / big / rare` 决定掉落池分组与后台产出倍率的作用范围。图鉴按底材展示全部词缀与区间，另有
「📍 钓点」分类可看该钓点实时产出概率；**组件订阅提醒**命中时背包红标 + 浏览器图标闪烁 + 写入日志。
背包里的渔获 / 材料 / 宝匣悬停有简介浮标、点击开完整简介（用途与产地按机制现算，不写死说明）。

**角色 · 钓竿**（页签）：7 个部位（竿身 / 线组 / 钩 / 饵 / 卷线器 / 配件 / 饰品栏位），装备走子页面弹窗
（筛选 / 排序 / 装备），换装时原样退回背包；`/api/bd/set` 由服务器校验部位与组件目录并落盘，
钓速变化即时重置进行中的循环。槽位上线上限 8 根（第 1 个免费，之后 1w / 5w / 10w / 20w / 40w / 80w / 160w），
可命名 / 收起保存 / 一键切换；**已保存钓竿的配件被锁定**（不可单独出售，背包与交易里显示 🔒），
但**整根钓竿可在市集「🎣 钓竿」分类出售**（逐件展示词条）。钓竿页签另有 **🧠 自动配装**配装器：
从背包（含当前已装那件）检索七个部位，按属性优先级求最优组合并一键装配；每行可设目标下限 / 上限，
滑块轨道两端就是该属性当前能落到的**可达区间**（改任意一项属性都会实时重算其余属性的区间与手柄位置）。

**宝匣（沉船打捞，「🎁 开箱」独立页）**：残片 + 金币合成宝匣、开箱产出组件，四档每档消除一层随机：

| 档位 | 残片 | 金币 | 基底 | 品质 | 词条数 | 消除的随机 |
|---|---|---|---|---|---|---|
| Ⅰ 沉船宝匣 | 8 | 8,000 | 随机 | 稀有 65% / 史诗 35% | ≥2 | 「1 词条垃圾」 |
| Ⅱ 深潜宝匣 | 20 | 30,000 | **自选部位** | 稀有 50% / 史诗 50% | ≥2 | 基底范围 |
| Ⅲ 深渊宝匣 | 45 | 90,000 | **自选底材** | 必定史诗 | **满池** | 基底 + 品质 + 词条数 |
| Ⅳ 海王遗匣 | 100 | 300,000 | 自选底材 | **必定神话** | 4 条(50%) / 3 条(50%) | 词缀池边界 |

合成产出的是**宝匣物品**（可囤积、可市集交易、可以物易物），开箱才产出组件；宝匣与整根钓竿
**不可卖给系统商店**（防「买残片 → 合成 → 卖商店」套利）。Ⅳ 档掷中 4 条时池内优先填满、不足部分用
**池外词缀**补足（区间刻意更弱且恒为正，界面标 ★ 池外）；后台可设**突破保底**（连续 N−1 次未突破则
第 N 次必出，`0` = 关闭）与四档成本，池外区间也在「🎁 宝匣配置」里配置。残片产自落日海湾·礁石区，
钓竿「材料概率」词缀可提高产出。**边界取值**：突破件与投入龙宫宝珠的熔炼，每个数值掷两次取
离区间边界更近的那次（极值更易出现）。

**工坊 · 熔炼**：放两件**同部位**组件（主件保留、副件熔毁）各选一条词条，熔炼后主件的词条就是这两条
并重新 roll 数值 —— 是除宝匣之外唯一能跨出词缀池边界的途径。四项规则（默认全开，后台可调）：
副件**连区间**一起提供（按副件自己的底材区间取值）、补缀**不受底材池限制**（可补 6 类中结果尚未拥有的
词缀，界面标 ★ 池外）、补缀后**词条数上限 3**、补缀按**池外区间**取值（与宝匣突破件共用同一份配置）。
**投料**是「词缀定向器」：份数最多的材料决定要补的词缀，投得越多成功率越高、花费越高；投料区只列出
「对应词缀还不在熔炼结果里」的材料（与服务端校验同一套判据）。**龙宫宝珠**（可选、至多 1 个）把 roll
改为掷两次取边界值；**残片保留**（至多 10 片，不计入投料）成功时按每片 10% 把主件的池外词缀按原值保留。
默认基础成功率 50%、每份材料降低失败率 2 个百分点、补缀成功率 = 投料份数 × 8%（上限 95%）、
金币 = 基础 5000 + 每份 900 + 宝珠 20000。**失败结算**：副件 / 投料 / 残片熔毁、金币照扣，
且主件被熔掉**选中的那条词条**（其余词条与品质保留退回背包）。

| 材料 | 品质 | 对应词缀 |
|---|---|---|
| 反光假饵 / 诱饵包 / 耐磨绳 | 普通 | 技巧 / 稀有度 / 体型 |
| 沉船宝匣残片 | 稀有 | 材料概率（另有「残片保留」「熔炼保护」两种用法；v0.16.0 起重铸不再用它） |
| 潮汐砂 / 龙鳞碎屑 | 稀有 / 史诗 | 钓速 / 双钓 |
| 龙宫宝珠 | 史诗 | 催化剂（不指向词缀）；v0.16.0 起也是**重铸材料**（基础 1 颗 / 指定第 n 条额外 n 颗） |


**重铸**（工坊页签二，v0.16.0 改版）：放一件**宝匣产出的神话组件**，用**龙宫宝珠**把词条数值重新掷一遍 ——
类型与条数不变、不会失败（可选「至少不比原来差」）。基础消耗默认 **1 颗宝珠**（后台「⚒ 工坊配置」可调）重 roll 全部词条；
**额外投入宝珠可以把重铸指定到某一条词条**——点词条行即选中，第 n 条额外消耗 n 颗（第 1 条 +1、第 2 条 +2…），
此时只有那一条的数值会变、其余原样保留。**熔炼预览**逐条给出「当前值 → 预计区间」与区间来源（池内 / 突破 / 催化），
并附结果预览卡（几词条 / 是否满池）。

**经济**：**商城 · 收购**（原系统商店）是单乘数供需模型 —— 每件经济物品（渔获 / 材料）维护价格乘数
`m ∈ [地板, 天花板]`（默认 40%~200%），实际价 = 基准价 × m；售出按比例下压（默认约 −0.7%/件），
闲置以时间常数（默认 60 分钟）向目标价指数回升（组件为固定价，不走供需）；可查走势图与流水。
**自动售出**支持「全部鱼」或单鱼规则（基准价百分比线 / 绝对价格线任一达到即卖，浮动接受值可提前成交），
规则逐账号保存。**商城 · 市集**（原开放市集）：每人默认最多同时挂 40 单（后台「账号管理」按账号调整，0 = 不限），
时长 6 / 12 / 24 小时对应上架费 1% / 3% / 5%（下架不退），成交收 10% 交易税（卖家承担）；
支持部分购买、整根钓竿与宝匣交易，可按组件词条类型 + 数值区间筛选。**在线交易**为以物易物、
双确认、0% 税，任一方改动物品即重置双方确认并冷却 3 秒、期间锁定背包、掉线自动取消。
**商城 · 限购**：金币直购官方商品，按后台刷新时间（默认 04:00）划分周期、跨点惰性重置。

**记录与社交**：「📖 图鉴 · 🏆 记录」按鱼种分卡片，可看该鱼全服**前十大 / 前十小**（每位玩家每榜只留一条最好成绩），
**「📜 日志 · 🏆 纪录」只记自己产生的纪录**（全服播报仍在横幅上，但不再把别人的成绩写进我的日志）；
全场最大纪录置顶（贴图缩放 / 偏移后台可调）；任一榜单更新都经 SSE 在顶部横幅播报。横幅分纪录轨
（排队播放）与公告轨（后台发布，可自定义颜色 / 队列 / 停止 / 查看实时观看人数）两条独立轨道，
显示时页面整体下移不遮挡内容。**全服动态通知等级** `all` / `uncommon` / `offrange` / `records` / `none`
只影响广播，钓者自己的推送不受影响。**反馈**按类型提交，默认 24 小时 CD、可花金币（默认 10000）
立即结束，管理员可逐条切换状态并发放金币奖励。**日志页**分列记录 🐟 渔获 / 🖥 系统 / ✅ 交易 /
🏆 纪录 / 🔔 订阅提醒，本地按账号保留最近 300 条。

## 测试

后端入口（Go）：

```bash
npm run go:build      # go -C server-go build ./...
npm run go:vet        # go -C server-go vet ./...
npm test              # go -C server-go test -count=1 ./...
```

真库集成用例需要 `FISHING_GO_TEST_DATABASE_URL`（隔离 PostgreSQL 的 `fishing_test` bootstrap 库）；
未设置时这些用例会明确跳过，所以“全 ok”不等于集成通过。完整命令、Docker/便携 PostgreSQL 用法和
只读存档扫描见 [server-go/README.md](server-go/README.md)。

前端浏览器回归（真实 Chrome，8 个套件）：

```bash
node tests/run-all.js                      # 并行跑全部前端套件
FISHING_TEST_ONLY=settings node tests/run-all.js
```

套件清单：`admin-interactions`（后台交互）· `desktop-zoom` · `inventory-pagination` · `mobile-layout` ·
`scene-performance`（Canvas 场景）· `settings`（设置面板）· `smelt-workbench`（熔炼工作台）·
`workshop-market-regression`。它们只用浏览器渲染前端：页面内自带桩服务或 `page.route` 拦截，
不启动后端进程，因此不需要数据库。

```text
FISHING_TEST_ONLY=settings,smelt-workbench   只跑指定套件
FISHING_TEST_JOBS / FISHING_TEST_TIMEOUT     并行度 / 单套件超时
FISHING_TEST_MODULES / NODE_PATH / CHROME_PATH   playwright-core 与浏览器位置
```

- **测试依赖不随仓库分发**：`playwright-core` 需自行安装到项目 `node_modules`，或用
  `NODE_PATH` / `FISHING_TEST_MODULES` 指定（`run-all.js` 会自动使用项目同级的
  `../fishing-test-modules/node_modules`）；浏览器优先 `CHROME_PATH`，否则自动探测 Chrome / Edge。
- 静态检查：`npm run go:coverage`（旧接口 method + path 对 Go 网关的静态覆盖，冻结分母在
  `server-go/api/legacy-inventory.json`）、`npm run go:coverage:test`。
- 其他 Go 侧检查：`node --test tests/migration-fixture.test.js`（迁移夹具规则）。
  `tests/go-rewrite-browser.test.js` 不是独立套件：它由 Go 测试
  `TestIntegrationLegacyBrowserConfigBannerParty` 通过标准输入驱动，需要隔离数据库、Chrome 和

### v0.25.0：后台 TOTP 自助绑定、品牌统一为 DeepFish 与发版链路加固（2026-09-26）

- **后台验证器自助绑定**：「👥 账号管理」页可直接为已授权管理员生成 / 轮换 TOTP 验证器密钥。此前只有运维能在服务器跑 `cmd/admin provision`，新管理员授权后必须等运维介入才能登录后台；现在在行列点「验证器」、二次确认即可拿到 Base32 密钥与 `otpauth://` 链接（只在这一次响应里返回，关窗即查不到）。服务端 `identity.NewMFASecret` 用 `crypto/rand` 生成 20 字节密钥，落库的是与运维入口相同的 AES-GCM 密文，同时把 `mfa_last_step` 重置为 -1、注销该账号其它后台会话（给自己轮换时保留当前会话），并写 `admin_audit` 的 `users/totp`；「是否管理员 / 是否封禁」的资格检查与锁 `player_state` 在同一事务内完成，撤权与之并发也不会留下密钥。密钥不进入审计、日志与账号列表投影，玩家的登录、钓鱼会话与实时流不受影响。

- **发版传输改走并行分片**：部署 job 原来把约 43 MB 发行包按 4 MiB 分片在一条多路复用 SSH 连接上顺序写，在这条约 245 ms、约 13% 丢包的国际链路上单条 TCP 流只有约 25 KB/s，每个版本都会在预算内被中止（v0.24.0 的部署就是这样失败的）。现在由 `tools/release/push-linux-package.sh` 负责包本体：分片落在绝对偏移、每片一条独立连接并关闭多路复用、单片滞留或摘要不符只重传该片、上传前先比对两侧分片摘要（重跑只补缺片），最后由服务器整体校验归档 SHA-256 才调用固定部署入口；部署 job 上限 30 → 40 分钟，并固定检出当前工作流修订，重试旧标签也会用上新上传器。发送端另有 `tools/release/tune-lossy-path.sh` 尽力打开 `fq` / `BBR` / 路径 MTU 探测（被 Runner 镜像拒绝时只记录内核实际取值，不影响发版），并新增手动工作流 **Probe Linux deploy transfer**：用同一个上传器把已发布的包写进 `incoming/.transfer-probe/<run>/` 量链路，结束即删除，不碰任何服务。
- **清档保留运营状态**：`reset fresh` 此前会把已发布的运营配置（`catalog_head` / `catalog_releases`、`feature_head` / `feature_releases`）与官方 Wiki 内容（`wiki_guides` / `wiki_sections` / `wiki_updates`）随玩家表一起清空，生效目录因此回落到二进制内置默认值、运营改过的正文与更新日志丢失。现在两者在「存在发布 / 存在官方内容」时整表保留，只清理玩家投稿、投稿账号与其修订历史；`accounts` / `asset_operations` / `command_results` 改为按外键顺序裁剪且不重置序列，新账号接着既有编号继续。预演与执行共用同一组谓词，输出新增 `retained` 字段。
- **缺段目录回填**：正式服的发布头仍指向 v0.23.4 的目录发布，早于 v0.24.0 新增的 HUT 段，`HutConfig` 读到零值后晒场升级、翻新、宠物喂养与角色加点全部被拒、晒场也不产出。现在 `catalog.Current` / `ByVersion` 会用内置快照回填发布里没有的常量与默认值（发布里有的名字仍然优先，运营覆盖与固定重试保持可复现，发布本身仍要求完整快照），后台徽章不再拿空等级曲线计算也不再报缺失 HUT 段，控制台与前端预检不再把宠物 / 角色加成上限算两遍（此前会把健康配置判成超过 3,190 线）。

### v0.21.4：钓速、技巧与材料概率调整（2026-09-20）

- Go 钓鱼排查修订（2026-09-23）：新库建表后还须执行 `go -C server-go run ./cmd/catalog defaults` 初始化物品定义；原启动检查未拦截缺定义的数据库，会导致开钓成功但首竿发奖反复回滚。现于启动和就绪探针只读校验生效规则所需定义；同时修复 SSE 心跳忽略 `connection_expired` 业务状态、租约过期后无法自动恢复钓鱼的问题。部署与验证边界见 [排查报告](docs/go-rewrite/reports/FISHING_ROOT_CAUSE_2026-09-23.md)。

- 默认基础抛竿间隔 **10000ms（10 秒）**，最短间隔仍为 800ms；钓点独立间隔只替换基础值。默认公式 `interval / (1 + speed / 100)` 可在后台「公式管理 → 抛竿间隔」修改。这里 `interval` 为钓点基础值再乘钓点速率系数 `1 - clamp(钓点钓速,-100,95)/100`，`speed` 为钓竿与全服加成之和（默认上限 100，可配置）；其余词条变量也可用于公式。计算结果取整并应用最短间隔，上限为 1 小时以避免计时器溢出；非有限值或非正数回退默认公式。
- 材料词条使当前钓点所有材料权重乘以 `max(0, 1 + material / 100)`，包含战利品组内材料；同步调整组的外层权重，保持非材料权重不变。后台材料产出倍率、稀有度仍先按已有规则计算，材料词条在该结果上修正。后台模拟器同步显示材料词条的真实分布。
- 默认上钩公式：设 `F(x) = max(0,x)^2 / (3025 + max(0,x)^2)`，概率（百分数）为 `clamp(min(interval / 60, (300 + 140*F(speed) + 80*F(skill)) / (3.6*(1 + max(0,speed)/100))), 0, 100)`。在上钩公式里 `interval` 指**最终抛竿间隔（ms）**，`speed` 仅取钓竿钓速（保留 v0.20.3 的规则），`skill` 为钓竿与钓点技巧之和。默认 10 秒基础、无全服加成/双钓时：

| 钓速 / 技巧 | 最终间隔 | 单竿上钩率 | 每小时期望成功上钩 |
| --- | --- | --- | --- |
| 0 / 0 | 10.000 秒 | 83.333% | 300.0 次 |
| 60 / 30 | 6.250 秒 | 68.476% | 394.4 次 |
| 90 / 60 | 5.263 秒 | 65.118% | 445.4 次 |

两个属性在 0–30 的期望边际收益递增，50 以上递减；60/30 为 90/60 的约 88.6%。默认公式限制每小时期望成功上钩最多 600 次（**不含双钓追加**）；管理员填写钓点独立上鱼率或自定义公式时以管理员配置为准。最短间隔、概率上限和自定义参数触发时曲线可能进入平台期。
