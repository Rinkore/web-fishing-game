# 钓鱼网站 v0.11.6（服务器权威 · 前后端分离 · 像素页游 UI）

零第三方依赖的多人联机网页钓鱼小游戏。**所有处理逻辑在服务端**：钓鱼循环、掷骰、
词缀加成、资产结算、钓竿配置均由后端权威执行；前端只发指令、收 SSE 广播、渲染。
纯原生 Web 前端 + Node 内置 `http` 模块后端，游戏数值目录前后端共用一份（UMD）。
桌面与手机端各自设计排版（手机端为底部标签栏 + 单栏内容）。

## 数据存储

**运行时数据默认存放在用户「文档」目录**，与程序文件分离 —— 升级 / 覆盖安装不会丢存档：

```
Windows:  %USERPROFILE%\Documents\web-fishing-game\
macOS/Linux:  ~/Documents/web-fishing-game/   （无 Documents 时退回用户主目录）
```

目录内按域 + 按账号分文件，**每次上鱼只重写该账号一个文件**，市集/记录/经济/配置各自独立，互不干扰：

```
<文档>/web-fishing-game/
├── accounts/<账号>.json   # 身份(用户名/盐/密码哈希) + 金币 + 背包 + 钓竿配置 + 图鉴 + 累计渔获
├── market.json            # 开放市集挂单与序号
├── records.json           # 大鱼榜 / 小鱼纪录 / 前十大 / 前十小 / 全场最大
├── economy.json           # 商店供需乘数 / 价格历史 / 交易流水 / 市集成交
├── config.json            # 钓场配置（含钓点地图坐标）/ 通知等级 / 上钩公式 / 双钓率 / 组件生成 /
│                          # 鱼类体型 / 宝匣保底与成本 / 工坊熔炼参数 / 商城商品与限购刷新时间 / 横幅队列 / 反馈规则
└── feedback.json          # 玩家反馈列表 + 每人下次可提交时间
```

- 可用环境变量 `FISHING_DATA_DIR` 覆盖数据目录（测试用临时目录即走此路径）。
- **旧数据自动搬迁**：首次启动时若文档目录尚无数据、而仓库内旧目录 `backend/data` 有数据，
  会整体拷贝到文档目录并打印 `[migrate] 数据目录已迁移到：…`；旧目录保留作备份，不再写入。
- 旧版单文件 `users.json` / `world.json` 也会在启动时幂等迁移为上述拆分结构。
- 数据目录已 gitignore（`data/` 与 `backend/data/`），含密码哈希与盐，绝不入库。

## 版本更新与前端缓存

前端 JS/CSS 会被浏览器缓存。为避免「服务器升级后，玩家浏览器里的旧前端请求到不兼容的新接口、
卡在进不去的页面」，实现了**版本守卫**：

- 版本号唯一定义在 `frontend/js/data.js` 的 `VERSION`（服务器与页面共用）。
- 服务器提供 `GET /api/version`（返回 `version` / `build`）。
- 页面启动时（`UI.init` 最先）比对本地 `VERSION` 与服务器版本，**不一致则带 `?v=&t=` 查询参数
  强制整页重载一次**，绕过 HTML/JS 缓存；用 `sessionStorage` 记录本次会话已刷新，
  避免服务器版本异常时无限刷新死循环。
- 服务器对静态资源始终返回 `Cache-Control: no-cache`，每次重载都会向服务器校验。

## 本次更新（v0.11.6）

### 重连自动续钓（离线钓点记忆）

服务端更新后客户端会自动强刷重登（见上节）。以前断线即「人走竿收」，重登后停在未出发状态，
得手动点回钓点。现在账号会记住**上次没有主动收竿的钓点**：

- 开始钓鱼 / 切换钓点时写入存档（`lastFishing`，随账号落盘 `accounts/<key>.json`），
  **断线、顶号、服务器重启都不丢**；
- 重建实时连接（`/events`）时服务端自动按原钓点续钓，并在 `init` 里带回钓速明细，
  前端不必再发一次 start 请求（顶栏立刻显示正确钓速）；
- 只有**玩家主动收竿**（点当前钓点取消 → `/api/fishing/stop`）才清除记录；
- 续钓前先校验：钓点已被删除 / 钓场被锁定或限时关窗 → 直接忘掉记录，不反复重试。
- 顺带修掉一个掉线判定问题：同一账号同时挂着多条实时连接时（强刷时新旧连接短暂重叠、多标签页），
  只有**全部断开**才算掉线；否则新连接刚续上的钓会被旧连接的清理逻辑掐掉。

### 背包：出售组件不再让分类重新排序

组件按底材分组，但组间顺序取的是「**组内第一个遇到的实例**」的品质与名字——出售那件（或整叠售罄）
就会让整组换位，表现为「卖一件东西，整个组件分类重排一遍」。现在组间顺序固定为
**部位（竿身→线组→钩→饵→卷线器→配件→饰品）→ 底材名**：两个键都只由分组身份决定、与实例无关，
出售后顺序恒定。组头也随之改为**汇总**显示——品质色取组内最高品质、词条标签取组内类型并集
（同组混品质时不再只反映那一个代表件）。

### 图鉴：可前往的钓点点亮为「已解锁」

钓点卡此前被「未解锁压暗」的通用规则整卡压暗，且只有一个从不生效的 `locked` class。现在按
**服务端是否锁定**（后台锁定 / 限时未开窗）分成两态：可前往的钓点整卡点亮（青绿描边 + 外发光 + 名称描边），
标注「✅ 已解锁 · 可前往垂钓」；锁定的钓场保持灰暗 + 灰色贴图，标注「🔒 尚未开放」。
钓点详情子窗口的同一句文案一并统一。

### 管理后台：账号授权并入账号管理

两页本来读同一份 `/api/admin/users`，现合并为一页「👥 账号管理」：列表新增**管理员**开关列
（可点表头排序），原有的搜索 / 联想 / 排序 / 编辑 / 快照 / 删除全部保留。
**不能撤销自己的权限**仍由服务端拦截（自己那一行的开关禁用）。

### 底部滚动网格动态层删除

`body::after` 那条持续滚动的斜纹网格（高 110px）已删除，页面底部不再有动态底纹。
钓点场景水与登录页水面是另外两层实现（共用 `@keyframes px-waves`），不受影响。

## 熔炼：副件区间与越池补缀（v0.11.5）

本版拆掉工坊熔炼的两处限制，四项都可在后台「⚒ 工坊配置 → 🧬 词缀搬移与补缀」配置（详见下文
「工坊 · 熔炼」章节里的「熔炼 · 副件区间与越池补缀（v0.11.5）」）：

1. **副件连区间一起提供**：副件搬来的词缀按**副件自己的底材区间**取值，而不是一律按主件口径
   （好底材当副件时，它的强区间会一起带过来；后台可切回旧规则）。
2. **补缀不受底材词缀池限制**：投料不再只能补「主件底材池里还没有的词缀」，而是可以补
   **全部 6 类里任何结果尚未拥有的词缀**。
3. **词条数上限可突破到 3**：默认允许「主 + 副 + 补缀」三条，越过品质上限（稀有 2）与底材池长；
   上限可在后台收到 1（等于禁止补缀）~ 6。
4. **补缀区间与突破区间同源**：补缀词缀按**池外（突破）区间**取值，读的就是宝匣突破件那份配置，
   后台改「🎁 宝匣配置 → 🎲 池外词缀数值区间」时两边一起变，并经 `componentcfg` 广播即时同步到在线玩家。

四项都是**开关 + 可配数值**，全部关掉即退回 v0.11.4 口径。熔炼预览现在逐条列出结果词缀的
**区间来源与具体区间**（如「技巧：副件区间 +8 ~ +14%」）。

## 界面刷新：就地更新（v0.11.4）

上鱼、出售、行情变化都是高频广播。原先它们统一走「`main.innerHTML=''` + 整页重建」，
于是**每钓到一条鱼，你正在看的页面就会重建一次**：地图节点与水面动画从头播、渔获日志整列重播入场动画、
展开的组件分组被收起、列表按新价格重排、正在填的数字框被冲掉。本版把这些高频路径改成**就地更新**：
结构不变就不重建，只改「真的变了」的那几个数字与行。

- **钓鱼页**：`fishingSig()` 给左栏算一个结构签名（地图页签 / 钓点与增益 / 所点与所在钓点 / 是否在钓鱼）。
  签名一致时走 `patchFishingLive()`——只更新钓场卡片人数、实况「同钓点 N 人」与玩家卡（内容签名变化才重建那几行）、
  状态条文案，以及**渔获日志只把新条目插到最前面**（旧行保持原 DOM，滚动位置与入场动画都不重播）。
  地图节点、水面/飞鸟场景、钓点卡片全程原样保留。
- **工坊**：资产广播（上鱼/售出只改背包与金币）走 `wsPatchAssets()`——原地更新各材料「持有 N」、
  禁用态与底部预览，**投料份数输入框的焦点、光标与已填数字都保留**。
- **市集**：资产广播只重画右栏「我的背包（上架）」；历史订单列表**缓存上次结果**先画旧数据再静默刷新，
  不再每次重绘都闪一下「加载中…」（`.market-history` 的滚动位置也纳入重绘保持）。
- **背包**：出售后走 `patchInventoryRow()`——只改那一行的数量/小计、必要时移除该行并同步组头件数；
  顶部/右栏概况（物品种类、总件数、预估总价、各分类计数）一并就地重算。
  **不再按新价格重排列表、不再收起展开的组件分组**（`doSell` 也刻意不走内部会 `refreshAll()` 的 `call()` 助手）。
- **顶栏**：chips 的 HTML 与上次一致就直接返回，不再无谓重建整条顶栏。
- **通用输入保护**：`mainInputFocused()`——主区内任何输入框/下拉获得焦点时，广播只刷顶栏与导航，
  不重建主区（交易页除外，它有自己的草稿机制）。
- **底部水波带**：`body::after` 曾加 `will-change: background-position` 提到独立合成层。**v0.11.6 起整条删除**
  （见「本次更新」），底部不再有持续滚动的斜纹网格。
- **输入框文字统一亮色**（`--px-input` #e9f6ff + `color-scheme: dark`）：此前没有通用 `color` 规则，
  深底上的输入文字吃浏览器默认近黑色——工坊投料份数、钓竿改名/存档命名、市集筛选、商城数量都读不清。
  同时给没有 `padding` 的 `.ipt`/裸 `input` 补了内边距，文字不再贴着描边。

## 组件系统（v0.8 大改）

组件不再是「ID 即效果编码」，而是**底材 + 随机实例**：

- **底材（base）**：组件模板，定义部位、基准价与「可拥有词缀池」（每条词缀含数值区间），
  如竿身底材 `rod_bamboo`（竹制短竿）可拥有 `钓速 +8~+14` 与 `体型 -6~+4`。
- **品质（quality）**：**普通 / 稀有 / 史诗 / 神话**四种（`common` / `rare` / `epic` / `mythic`），决定一件组件最多能带几条词缀
  （**1 / 2 / 3 / 4**），并给实例基准价倍率（1 / 1.5 / 2.4 / 3.6）。渔获与组件**共用同一套品质**：
  大型鱼按价值归入稀有（≤180）与史诗（≥210），**「大鱼」不再是品质**（v0.11 修正，见「品质系统」章节）。
  图鉴中「满词条」实例的品质显示为**金色**（仅背包/市集/装备弹窗；图鉴条目按品质正常显示，不再带满词条标记）。图鉴另有**「📍 钓点」分类**：每个钓点一张卡，点开可看该钓点能钓到什么与**实时产出概率**（与后台掉落池/增益/上鱼率配置一致，后台改动经 SSE 推送即时同步到打开中的详情）。
- **实例生成**：任何途径产出组件时，**先按品质权重定品质 → 再抽取 1 至「底材池长 ∩ 品质上限」条词缀
  → 最后逐条 roll 数值**。
- **实例身份 = 内容签名**：`底材#品质#词条码+数值,…`（词条款按底材池顺序规范化），
  如 `rod_bamboo#rare#spd+12,size-3`。词缀组合与数值完全相同的组件天然堆叠，背包仍是 `{签名: 数量}`。
- **修饰词**：由词缀组合推导（满词条且无负词条 → 完美的 等），**规则可在管理后台配置**（见下）。
- **图鉴**：按底材登记，展示该底材可拥有的**全部词缀与数值范围**；持有满词条实例时标注金色。点击卡片在**子窗口**查看详情。
  网格为**等高布局**（`grid-auto-rows: 1fr`），所有卡片对齐到最高的一张。
  产地取自服务器下发的钓场目录（连接时经 SSE `init` 同步），管理后台改过掉落池也会一致。
- **市集**：可按组件词条类型 + 数值区间筛选搜索；挂单行每条词缀后用括号标注该词缀的**数值范围**。
- 旧存档（v0.7 编码 id，如 `rod_spd15_size-5`）启动时自动升级为实例签名（选同部位中词缀类型覆盖最多的底材）。

### 组件生成配置（管理后台「🧩 组件生成」）

生成参数全部可调，保存即对全服生效（落盘 `config.json`，并随 `/api/version` 下发给前端）：

- **品质掉落概率**：普通 / 稀有 / 史诗的相对权重（默认 0.62 / 0.30 / 0.08）。
- **词条数量概率**：每个品质在「1 / 2 / 3 条」上的相对权重。
- **数值 roll 模型**：`linear` 均匀 / `normal` 正态（偏中值）/ `skew` 偏态（偏低值）。
- **底材词缀数值范围**：为任意底材的任意词缀覆盖最小~最大取值。
- **修饰词规则**：按顺序取第一条命中；条件含「满词条 / 无负词条 / 净收益区间 / 词条数区间」。
- 提供「试算 2 万次」预览品质分布与词缀均值；「恢复默认」一键还原。

## 品质系统与「技巧」词缀（v0.11 修正）

全站品质只有四种：**普通 / 稀有 / 史诗 / 神话**（渔获与组件共用同一套名称与配色）。
此前版本把渔获的「大鱼」档位当成第五种品质（金色 + 👑 皇冠前缀），本次已修正：

- **渔获品质**：原来的 14 种大型鱼按价值拆成 **稀有（120~180）** 与 **史诗（210~350）**；
  普通鱼仍是普通，稀有鱼档位仍是稀有。👑 前缀与「🐟大鱼」标记全部移除。
- **掉落档 ≠ 品质**：`FISH.common/big/rare` 三个数组仍是**掉落档**（决定掉落池分组与后台「产出倍率」的作用范围），
  后台里显示为「普通鱼 / 大型 / 稀有鱼」，与品质是两个维度。
- **钓竿词缀「大鱼概率」→「技巧」**：旧词缀直接放大大型鱼掉落权重，与钓点增益、产出倍率重复且无法表达钓技；
  新的**技巧**词缀是**上钩率公式里的一个变量** `skill`，公式默认 `clamp(90 + skill, 0, 100)`：
  没有技巧词缀时等价于旧版的平值 90%，装备技巧件后按公式提升上钩率。
  **代码里不写死任何「技巧 = +X% 上钩率」的提示**，钩率完全由后台「🧮 公式管理」的公式决定；
  后台公式页的「可用变量」区把 `skill` 单独列出并给出示例（含试算输入框）。
- **钓点增益**比组件词缀多一类「大鱼概率」：增益是钓场/钓点级别的产出倍率，后台仍可给钓点加「大鱼概率 +30%」。
- **旧存档**：启动时的迁移会把背包 / 当前装配 / **钓竿槽位** / 市集挂单（含**整竿标识内部的配件签名**）
  里的旧签名（短码 `big`）规范化为 `skl`；另提供**本版专用**的修复脚本 `tools/fix-save-v011.js`（见下），
  用于跨版本升级或手工校对。

## 商城（每日限购 · v0.11 启用）

侧边栏「🛒 商城」：**金币直购**官方商品，每件商品可设金币价与**每日限购**。

- **限购按刷新时间划分周期**：后台设「每日刷新时间（HH:MM，服务器本地时间）」，跨过刷新点即重置为满额。

## 工坊 · 熔炼（v0.11 新增）

侧边栏「⚒ 工坊」：放两件组件（**主件**保留、**副件**熔毁），各选一条词条，熔炼后**主件的词条就是这两条**
并重新 roll 数值——把副件独有的词缀搬到主件上，是除宝匣之外唯一能**跨出词缀池边界**的途径。
v0.11.5 起副件**连词缀带区间一起提供**，且投料补缀**不再受底材池限制、可补到 3 条、按池外区间取值**。

- **取值区间**：选中的主件词缀按主件底材区间重 roll。**副件搬来的词缀按副件自己的区间取值**（v0.11.5）：
  该词缀在副件底材池内就按副件区间，不在副件池内（副件本身是突破件）才回退「池外词缀区间」——
  即副件**连词缀带区间一起提供**。后台「⚒ 工坊配置 → 🧬 词缀搬移与补缀」可关掉该行为，回退旧规则
  （在主件池内按主件区间）。
- **投料（可选）**：材料即「词缀定向器」，每种材料对应一个词缀类型；投料份数最多的那种材料决定要补的词缀。
  v0.11.5 起补的词缀**不再受主件底材词缀池限制**：候选 = 全部 6 类词缀里熔炼结果还没有的那些，
  所以普通底材也能被补出它本来没有的词缀；**补缀后词条数上限默认 3**（可越过品质上限与底材池长，
  即「主 + 副 + 补缀」三条）。补缀词缀默认按**池外（突破）区间**取值 —— 与宝匣突破件共用同一套区间，
  后台改「🎁 宝匣配置 → 🎲 池外词缀数值区间」时，补缀的取值区间随之变动（改动经 SSE 即时同步到玩家端预览）。
  投料越多：补缀成功率越高、金币花费越高。
- **组件选择**：主件 / 副件的挑选用的是**与「钓竿配置 · 装备组件」完全相同的子页面**（同一套部位/词条筛选、排序、
  卡片与「出售 / 上架」入口），主件选择器可跨部位浏览，副件选择器只列**主件同部位**的组件。
- **同部位限制**：主件与副件必须是同一部位（竿身配竿身、钩配钩）；前端在选择器里就限制住，服务器再做一次校验，
  跨部位提交会被拒（避免把竿身的词缀搬到钩上这种语义混乱的产出）。
- **龙宫宝珠（可选）**：roll 值改为掷两次取**靠近区间边界**的那次（与海王遗匣完全相同的规则）。
- **残片保留（可选，v0.11.3）**：主件是**海王遗匣产出的神话件**（即带池外词缀的突破件）时，可另投**至多 10 片沉船宝匣残片**。
  残片**不计入投料**——不改变熔炼成功率、补缀成功率与金币花费，只消耗残片本身——成功时按
  **每片 10%**（10 片即 100%）的概率，把主件的**池外（突破）词缀按原值保留**到熔炼结果上
  （与选中/补缀词条同类型的会去重，不会出现两条同类词条）。片数上限与每片概率都由后台可调。
- **成功率**：默认熔炼基础成功率 **50%**；每份材料降低失败率 2 个百分点（后台可把该系数改为正数，即「投料越多越冒险」）；
  补缀成功率 = 投料份数 × 8%（上限 95%）。
- **失败结算（v0.11.3 改版）**：副件、投料、残片熔毁，金币照扣，且**主件被熔掉「选中的那条词条」**
  （其余词条与品质原值保留，退回背包；只有一条词条的主件会变成 0 词条的底材本体，不会被销毁）。
  结果窗口会给出受损后的主件卡片与被熔词条，便于判断损失。
- **材料对应表**（后台「⚒ 工坊配置」只读展示）：
  | 材料 | 品质 | 对应词缀 |
  |---|---|---|
  | 反光假饵 | 普通 | 技巧 |
  | 诱饵包 | 普通 | 稀有概率 |
  | 耐磨绳 | 普通 | 体型 |
  | 沉船宝匣残片 | 稀有 | 材料概率（另有「残片保留 / 重铸」两种用法） |
  | **潮汐砂**（新增） | 稀有 | **钓速** |
  | **龙鳞碎屑**（新增） | 史诗 | **双钓** |
  | 龙宫宝珠 | 史诗 | 催化剂（不指向词缀） |

  即：已有材料先覆盖 4 类词缀，不足的两类（钓速 / 双钓）用**品质更高的新钓材**补齐。
- 接口：`GET /api/workshop`、`POST /api/workshop/smelt`、`POST /api/admin/smelt/config`。

### 熔炼 · 残片保留（v0.11.3）

同一件「沉船宝匣残片」在工坊里有两种进阶用法，规则刻意保持同一判据（**神话品质 = 宝匣产出身份**）：

| 用法 | 适用主件 | 消耗 | 效果 |
|---|---|---|---|
| 投料 | 任意组件 | 计入投料份数 | 指向「材料概率」词缀、压低失败率、抬高花费 |
| 残片保留 | 神话主件（含突破件） | 1~10 片，**不计入投料** | 成功时按每片 10% 保留主件的池外词缀 |
| 重铸（另一页签） | 神话组件 | 10 片 + 0 金币 | 重 roll 全部词条数值（类型与条数不变） |

- **为什么值得投**：熔炼会把主件词条改写成「选中的两条（+ 补缀）」，突破件靠宝匣补出来的池外词缀
  本来会一起消失；投残片就是把这些**只能在宝匣里出现的词缀**救回来（按原值，不重 roll）。
- **不划算的情况会被服务器直接拒绝**（不烧残片）：主件不是神话品质、主件没有池外词缀、片数超过上限、
  残片持有不足，都会返回 400 并给出原因；前端在选好主件时就只对符合条件的组件显示这个入口。
- **失败也消耗**：残片与投料一样在失败时熔毁（这是「10 片 = 保底保留」的对价）。
- 后台「⚒ 工坊配置 → 🛡 熔炼 · 残片保留」可改**每片概率**（默认 10%，可带小数）与**单次片数上限**（默认 10）。

### 熔炼 · 副件区间与越池补缀（v0.11.5）

这一版把熔炼的「取值范围」和「补缀边界」两处限制拆掉，四项都可在后台「⚒ 工坊配置」里配置：

| 规则 | 默认 | 说明 | 后台开关 |
|---|---|---|---|
| 副件连区间一起提供 | **开** | 副件搬来的词缀按**副件自己的底材区间**取值（不在副件池内 → 池外区间） | 副件连区间一起提供 |
| 补缀不受底材池限制 | **开** | 候选 = 全部 6 类词缀里结果还没有的那些（不再要求「属于主件词缀池」） | 补缀不受底材池限制 |
| 补缀后词条数上限 | **3** | 主 + 副 + 补缀，可越过品质上限（稀有 2 / 史诗 3）与底材池长 | 补缀后词条数上限（1~6） |
| 补缀按池外区间取值 | **开** | 补缀词缀按**池外（突破）区间**取值，与宝匣突破件同一套区间 | 补缀按池外区间取值 |

- **副件区间**：以前副件只提供「词缀类型」，数值一律按主件口径取（主件池内按主件区间，否则池外区间）。
  现在副件**连它自己的区间一起提供** —— 把「龙骨巨竿 · 技巧 +8~14」熔到「竹制短竿」上，就得到 +8~14 的技巧，
  而不是按主件口径落到池外的 2~6。区间取自副件的**底材可配区间**（管理后台「🧩 组件生成」里改副件底材区间，熔炼立刻跟着变）。
- **越池补缀**：以前投料只能补「主件底材池里还没有的词缀」，普通 2 条池底材补不出第 3 条；现在候选是
  **全部 6 类词缀里熔炼结果还没有的那些**，所以任何底材只要投对材料就能补出它本来没有的词缀（补出来的词缀在界面上标 ★ 池外）。
  仍然遵守「结果里已经有这条词缀就不能再补」，并且受**补缀后词条数上限**约束（默认 3，后台可收到 1 = 禁止补缀）。
- **补缀区间与突破区间同源**：补缀词缀默认按**池外（突破）区间**取值。它与宝匣突破件读的是**同一份配置**
  （`componentCfg.extraAffixRanges`），所以后台改「🎁 宝匣配置 → 🎲 池外词缀数值区间」时，
  工坊预览与实际掷骰会一起变 —— 广播 `componentcfg` 即时同步到在线客户端，不用刷新页面。
- **界面**：熔炼预览把结果的三条词缀逐条列出，并标注各自的**区间来源**与具体区间（如「技巧：副件区间 +8 ~ +14%」）；
  投料里「这次补不了」的材料标灰划掉；熔炼结果窗口也会回传三条词缀的实际取值区间。
- **完整兼容旧行为**：把上面四个开关都关掉（上限收到 2），就退回 v0.11.4 的熔炼口径，老玩家体感不变。

### 重铸（用残片重 roll 宝匣神话件）

把**全部词条的数值**重新掷一遍——类型与条数不变，只洗数值。

## 服务端版本更新（优雅热更 · v0.11 新增）

后台「🔄 版本更新」页：选中新版本要运行的 `.bat` 启动脚本并发布更新。

1. 立即向全服播报 **60 秒**的更新通知横幅（最高优先级轨道，带实时倒计时，不排队、不被公告轨阻塞）；
2. 横幅结束后 **5 秒**（宽限期，让在途请求写完），服务器**先停止监听让出端口**，
   再以独立进程拉起新版本的 `.bat`，最后**关闭当前版本**；
3. 玩家端在服务器重启后由版本守卫自动重连/强刷，无需手动操作；倒计时期间可随时**取消**（横幅立刻撤回）。

- 脚本必须位于项目目录内且以 `.bat` 结尾（防路径穿越）；把新版本解压到 `releases/<版本号>/` 后下拉会自动列出。
- 后台「演练模式」（API `dryRun`）只走流程不真的切换，便于灰度前验证。
- 接口：`GET /api/admin/update/list`、`POST /api/admin/update/start`、`POST /api/admin/update/cancel`；
  进行中的任务也会随 `GET /api/version` 下发，后连进来的玩家同样能看到倒计时。

## 宝匣合成（v0.10.2 · 沉船打捞）

侧边栏「🎁 宝匣合成」页：用「沉船宝匣残片」+ 金币合成宝匣，开箱获得组件实例。
四档梯度，**每一档消除一层随机**——这是这套系统的核心设计，不是四条并列的抽奖：

| 档位 | 残片 | 金币 | 基底 | 品质 | 词条数 | 消除了哪一层随机 |
|---|---|---|---|---|---|---|
| Ⅰ 沉船宝匣 | 8 | 8,000 | 随机 | 稀有 65% / 史诗 35% | ≥2 | 「1 词条垃圾」 |
| Ⅱ 深潜宝匣 | 20 | 30,000 | **自选部位** | 稀有 50% / 史诗 50% | ≥2 | 基底范围（29 选 1 → 4~5 选 1） |
| Ⅲ 深渊宝匣 | 45 | 90,000 | **自选底材** | 必定史诗 | **满池** `min(池长,3)` | 基底 + 品质 + 词条数 |
| Ⅳ 海王遗匣 | 100 | 300,000 | 自选底材 | **必定神话** | **4 条（50%）/ 3 条（50%）** | 词缀池边界 |

- **合成与开箱分两步**：合成产出的是**宝匣物品**（进背包），可囤积、可市集交易、可与玩家以物易物；
  开箱才产出组件。**宝匣不可卖给系统商店**（同整根钓竿，防止「市场买残片 → 合成 → 卖商店」的套利环）。
- **产出的组件可交易**，因此宝匣有真实的市场价格锚；残片来自落日海湾·礁石区（1.69%），
  钓竿的**「材料概率」词缀**能提高产出，后台「💰 经济参数 → 产出倍率 · 材料」是总闸门。
- **合成成本可在后台改**：「🎁 宝匣配置」页的四档成本（残片 / 金币）就是可编辑输入框，保存即同步玩家端与合成校验
  （无需重启）；档位的模式 / 品质权重 / 词条数等结构性配方仍写在 `data.js`，随版本发布。
- **突破件的数值 roll 两次取边界值**：池内与池外词缀的每个数值都掷两次，取**离区间边界更近**的那次
  （区间 `[-1, 8]`：掷出 `-1` 与 `6` 取 `-1`；掷出 `4` 与 `8` 取 `8`）。
  效果是极值更容易出现——这是「海王遗匣」相对于 Ⅲ 档的另一层价值，工坊熔炼投入龙宫宝珠时用同一套规则。
- **「部位」与「底材」的区别**：一个部位含 4~5 个底材（如竿身有竹制短竿/玻璃钢竿/碳素长竿/龙骨巨竿），
  且同部位不同底材是**取向差异而非强弱**（龙骨巨竿给大鱼/体型但**扣钓速**）。
  所以「自选部位」只是缩小范围、不保证取向，「自选底材」才完全确定——这是 Ⅱ 与 Ⅲ 档的分界。
- **神话品质（新增）**：`cap 4`、基准价倍率 3.6、**彩虹渐变**配色。**只能由宝匣产出**——
  后台「组件生成」的品质权重刻意不含 mythic，普通钓鱼掉落永远不会出神话件，否则宝匣的价值主张会被稀释。
- **突破件**：Ⅳ 档掷中 50% 时，词条数越过史诗的 3 条上限达到 4 条——池内优先填满、不足的部分用
  **池外词缀**补足（该底材词缀池里本没有的词缀，如给竿身补「双钓概率」）。
  池外词缀的数值区间**刻意明显弱于池内同类型**（如钓速 4~10 对照池内 8~38），且**恒为正**；
  否则 2 条池的弱底材补上强池外后会反超 4 条池底材，且终局件出减益词缀的体感太差。
  这套**池外区间**是唯一的一份配置（`componentCfg.extraAffixRanges`，后台「🎁 宝匣配置」里改）：
  工坊**投料补缀**的词缀也按它取值（v0.11.5，见「熔炼 · 副件区间与越池补缀」），改一处两边同时生效。
  区间可在后台「🎁 宝匣配置」覆盖。
- **特例**：海王徽记是全游戏唯一的 4 条池底材，Ⅳ 档对它**必出满池 4 条、不掷骰、不补池外**——
  否则「未中」分支会把它 4 条池里弃掉 1 条，让最贵的宝匣产出降级件。它也是唯一能真正抽满池的底材
  （旧版 epic `cap=3` 让它永远抽不满，神话 `cap=4` 正好补上）。
- **突破保底**：后台「🎁 宝匣配置」可设 N——连续 N−1 次未突破则第 N 次必出（命中即清零，`0` = 关闭）。
  参考期望次数：关闭 2.00 / N=4 → 1.88 / **N=3 → 1.75（推荐）** / N=2 → 1.50。
  N=3 把最坏情况从「无上限」压到 3 次，期望成本只降 12.5%。保底进度在卡片与开箱子窗口都可见
  （保底不可见就等于没做），触发时提示「⚡ 保底触发」。
- 开箱产出**登记图鉴**（按底材累计）；**突破件全服横幅播报**（复用纪录轨）。
- 界面标识：神话件用彩虹字 + 独立的「突破」标签（优先于「满词条」金色，否则和满词条史诗长得一样）；
  池外词缀用**点线下划线**区分，开箱结果窗口另有 ★ 说明。
- 接口：`GET /api/chest`、`POST /api/chest/craft`、`POST /api/chest/open`、
  `POST /api/admin/settings`（`chestCfg.pityN`）、`POST /api/admin/component/config`（`extraAffixRanges`）。
  档位配方写在 `frontend/js/data.js` 的 `CHESTS`（与组件底材/词缀池同一份目录，前后端共用）。

## 架构要点（服务器权威）

- **钓鱼**：`POST /api/fishing/start|stop` 在服务器启停钓鱼循环；服务器定时器掷骰
  （含钓竿词缀加成），渔获入库/图鉴/大鱼榜/动态全部在服务端完成，经 SSE 定向推送
  `catch` 与权威 `assets`；断线自动停竿。客户端无法伪造渔获（旧 `/catch` 已删除）。
- **账号**：注册**必填 QQ 号**（5-12 位数字）与**确认密码**（两次一致）；`POST /api/login` 登录、
  `POST /api/logout` 登出（使该 token 失效；无其他会话时断开实时连接）。顶号：同账号二次登录使旧会话失效。
- **钓竿配置**：`POST /api/bd/set` 由服务器校验部位与组件目录并落盘；钓速变化即时
  重置进行中的循环。`/api/profile` 只接受显示名，客户端上报 coins/inventory 一律忽略。
  装备组件为**子页面（弹窗）**：点部位卡片的「装备组件」弹出该部位可选组件列表（筛选 / 排序 / 装备），
  不再占用配置页下方整块区域。负面词条（如 `-5% 钓速`）以**红色**显示。
  装备 = 从背包取用 1 件；卸下或换装时原样放回背包（不再摧毁，可循环取用）。
- **钓鱼页布局**：右侧只保留「渔场实况 + 我的渔获日志」，**不再内嵌背包**（背包见独立「背包」页）；
  左右两栏等高，渔获日志撑满右栏，底边与左栏对齐。
  有**钓点增益**的钓点按钮会加 **⚡ 标记**（鼠标悬停显示增益明细）；渔场动态页的钓场卡片也会标 ⚡。
  钓场目录在连接时经 SSE `init` 下发，并在进入游戏时主动拉取 `GET /api/grounds` 兜底，
  因此**后进入或刷新过的玩家同样能看到增益标记**。
- **切换钓点**：钓点选择用 `pointerdown` 触发（并用 `closest` 命中子元素）。上鱼广播会整页重绘，
  若用 `click` 则在按下与松开之间重绘会丢失事件，表现为「切换钓点被上鱼卡住」；键盘激活仍走 click 兜底。
- **近期渔获**：非普通渔获（稀有/史诗）与组件入包时由服务器更新 presence 并广播。
- **体型加成**：钓竿「体型」词缀按百分比线性放大/缩小掷出的体型，**不设固定上限**
  （旧版曾硬性封顶 `上限×1.3`，导致高体型加成失效）。最小值保底 1cm。
- **双钓率**（v0.8.3 重做）：叠加值 A（百分比点数，50% 写作 A=50）→ 单次追加概率
  `P = A/(A+100) = 1 - 1/(1+A/100)`。判定：基础上钩 1 条；掷 < P 成功则额外 +1，
  再掷 < P 成功则再 +1；**最多 3 条**。概率分布：1 条 `1-P`、2 条 `P(1-P)`、3 条 `P²`；
  期望 `E = 1 + P + P²`。若世界配置了基础双钓率 B，则最终双钓概率 `1 - (1-B)(1-P)`
  （管理后台「公式管理」页可在 0–100% 调整 B，与上钩公式合并到同一页）。
- **渔获日志**：切换账号时会清空上一账号的渔获日志与临时状态（回归修复：曾残留串号）。
- **渔获记录**：大鱼 / 小鱼纪录按鱼种分卡片，**点击可看该鱼前十大 / 前十小**（`/api/records/top?id=&kind=big|small`）。
  两个榜单**每位玩家只保留一条最好成绩**（大鱼取其最大、小鱼取其最小），再排序取前 10。
  **全场最大纪录被破**时，服务器经 SSE `globalRecord` 广播，所有在线玩家网页顶部横幅滚动播报，
  **等整段字完整滚出屏幕后再收起**（按内容宽度动态定时，不再固定 5 秒硬关）。
- **横幅队列**：管理后台可发布多条滚动公告（内容 + 时长），玩家端**按队列顺序依次播放**；
  有内容且开启时**浏览器图标（favicon + 标题）闪烁**提示（标题可在管理页配置）。
  横幅显示时页面整体下移（`body.banner-open`），**不遮挡顶栏与内容**；开始新横幅会作废旧横幅的收尾回调，避免误取消。
- **系统商店**：出售数量由商店顶部控制条统一设定（加减按钮 + 手输），**对整个商店生效，直到下次被修改**；
  **两栏布局**：左侧商品网格，右侧「🤖 自动售出管理」栏（全部鱼规则 + 40 条鱼逐条列出规则状态与设置入口）；
  **筛选栏**（类别 / 仅显示我持有的 / 仅显示已设自动售出 / **排序：价格 / 涨幅 / 持有，再点同键反向排序**）；
  行情广播只刷新商品网格与右栏列表，**面板输入框不会被广播清空**；
  支持**自动售出**：可设「全部鱼」或单条鱼的规则——价格达到基准百分比、或绝对价格达到阈值时，
  背包里该鱼按系统行情自动卖出（钓到即卖；价格闲置回升越过阈值也会触发；可加**浮动接受值**

  可按组件词条类型 + 数值区间筛选搜索；挂单组件每条词缀后括号标注数值范围。

  保底计数按 `rec.chestPity[档位id]` 存账号文件，命中即清零、随存档持久化；配置改动经 SSE `chestcfg` 同步。

  改密码 / 显示名 / 金币（`users/update`）、
  **查看并编辑资产快照**（金币与背包，`users/snapshot`）、**删除账号**（需二次确认 `users/delete`，不能删除自己）；
  改密会使其所有会话失效。**市集管理**支持关键字（物品/卖家/账号）+ 类型 + 词条/数值筛选，以及时间/价格/数量排序。

  **横幅管理**页发布滚动公告并可管理队列与图标闪烁。

  `POST /api/feedback/skip` 花 10000 金币立即结束 CD；每条反馈带**状态标识**（已提交 / 已受理 / 已完成），
  玩家可见自己的状态，管理员在后台「反馈意见」页可逐条切换状态（`POST /api/admin/feedback/status`）；落盘 `feedback.json`。
- **前端请求超时**：游戏页与管理后台的 `fetch` 统一带 8 秒超时（`AbortController`），超时按网络错误处理，
  **GET 自动重试一次**（写操作不重试，避免重复提交）——偶发请求悬挂不会让页面停在「加载中…」；
  后台画界面时也会先确认容器还在（切页期间的迟到响应直接丢弃）。
- **版本**：`GET /api/version` 供前端缓存守卫比对。
- **测试辅助**：`FISHING_DEV=1` 环境变量开启 `/api/dev/seed|catch|rollsize|doublecount`（确定性回归用），
  正常部署不开启。

## 运行

### 集成模式（最简单）

```bat
run.bat
```

打开 http://localhost:9000 ，注册登录即可；多开浏览器标签 = 多真实玩家。

### 分离模式（前后端独立进程）

```bat
run.bat                 :: 窗口1：后端 API，http://localhost:9000
start-frontend.bat      :: 窗口2：前端静态服务器，http://localhost:5500
```

打开 http://localhost:5500 。前端 `API_BASE=auto` 会自动连接同主机的 9000 后端（后端已放行 CORS）。

前端也可以用任意其他静态服务器托管 `frontend/` 目录（nginx、GitHub Pages 等），或把
`frontend/js/config.js` 里的 `API_BASE` 改成显式地址（如 `https://api.example.com`）。

### 后端环境变量

| 变量 | 说明 |
|---|---|
| `PORT` | 监听端口，默认 9000 |
| `STATIC_DIR` | 指定前端目录；`none` 强制纯 API 模式（默认自动托管 `../frontend`，存在时） |
| `FISHING_DATA_DIR` | 数据目录覆盖（默认用户「文档」下的 `web-fishing-game`）；测试套件用临时目录隔离，避免清掉真实存档 |

## 测试

```bash
node tests/run-all.js   # 一键跑 e2e / auth-ui / fishing-interaction / bugfix / chest / v011 / ui-layout / admin / admin-ui
# 9 个套件并行执行（各套件端口与临时数据目录互不干扰），全量约 49 秒 / 1386 项
# v011 覆盖 v0.11 的功能：品质系统纠正 / 技巧词缀与公式 / 龙宫宝珠归材料 / 商城每日限购 /
#   宝匣成本与边界取值 / 工坊熔炼全流程（成功·失败结算·投料·宝珠·校验·同部位限制·残片保留·
#   v0.11.5 副件区间与越池补缀·词条数上限突破）/ 工坊重铸 /
#   钓点坐标 / 纪录贴图缩放与偏移 / 版本更新流程 / 存档修复脚本 / 龙宫宝珠清理脚本
# admin-ui 是从 ui-layout 拆出的后台页面场景：只依赖「一个玩家页 + 一个后台页」，
# 与游戏侧场景无状态耦合，拆开后两者并行跑，全量墙钟不再被单个套件卡住
#   FISHING_TEST_JOBS=3        并行度（默认 = 套件数，上限 16）
#   FISHING_TEST_ONLY=admin,e2e 只跑指定套件
#   FISHING_TEST_SHARDS=ui-layout:2  把某套件拆成 N 个并行分片（套件需支持 FISHING_TEST_SHARD）
#   FISHING_TEST_TIMEOUT=480000 单套件超时兜底（ms）
```

测试内部不做固定 sleep：服务器就绪、页面渲染、弹窗出现等一律用 `tests/_util.js` 的
`waitHttp / waitFor` 轮询等待 + 超时，条件满足即刻继续（既快又不脆）。ui-layout 里另有
`untilGet / untilSel` 两个助手，用于替代「点一下 → sleep(1s) → 读接口/DOM 断言」的固定等待：
轮询到条件成立即返回（本地往返通常几十 ms），超时则返回最后一次取值，让断言仍报出真实失败信息。
**只有真正等时间的地方才保留固定等待**（如「等过一轮 5s 自动刷新」「等一个 >3s 的钓鱼周期」）。

`run-all.js` 只保留关键行与有界尾巴，不再整份缓存各套件日志；每个单元一结束就立刻打印小结并
带上墙钟时间戳，所以进度是实时的，不必等全部跑完。切后台页请用 `clickAdminNav(name, sel)`：
它按「导航项变 active + 关键控件就绪」判断，**不要用标题变化判断**——重复点同一页时标题不变，
会白等满超时。

jsdom / playwright-core 不随仓库分发，装好后放到项目 `node_modules`，或用
`NODE_PATH` / `FISHING_TEST_MODULES` 指定位置（`run-all.js` 也会自动使用项目同级的
`../fishing-test-modules/node_modules`）。ui-layout 需要真实 Chromium 内核浏览器：
优先 `CHROME_PATH`，否则自动探测 Chrome / Edge。测试启动前会自动清理同端口的残留旧实例
（Windows 下测试进程被强杀时可能留下孤儿服务器）。
