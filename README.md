# 钓鱼网站 v0.10.3（服务器权威 · 前后端分离）

零第三方依赖的多人联机网页钓鱼小游戏。**所有处理逻辑在服务端**：钓鱼循环、掷骰、
词缀加成、资产结算、钓竿配置均由后端权威执行；前端只发指令、收 SSE 广播、渲染。
纯原生 Web 前端 + Node 内置 `http` 模块后端，游戏数值目录前后端共用一份（UMD）。
桌面与手机端各自设计排版（手机端为底部标签栏 + 单栏内容）。

## 项目结构

```
├── backend/
│   └── server.js        # 权威服务器：钓鱼循环/掷骰/钓竿配置/账号/商店/市集/交易/SSE 广播
│                        # 数据落盘用户「文档」目录（见下，按域 + 按账号拆分）；游戏目录 require 自 frontend/js/data.js
├── frontend/            # 纯静态瘦客户端，可部署到任意静态服务器
│   ├── index.html
│   ├── admin.html       # 管理后台页面（管理员账号登录，见「管理后台」章节）
│   ├── serve.js         # 本地开发用静态服务器（零依赖）
│   ├── css/style.css
│   ├── css/admin.css
│   └── js/
│       ├── config.js    # API_BASE 配置（默认 'auto' 自动探测）
│       ├── data.js      # 游戏数据目录（UMD：前端挂 window.GameData，后端 require）
│       ├── engine.js    # 客户端状态层：展示状态 + 指令发送（无游戏逻辑）
│       ├── net.js       # 网络层：指令 API + SSE 广播接收
│       ├── admin.js     # 管理后台页面逻辑
│       └── ui.js        # 页面渲染与交互
├── tests/               # 8 个测试套件 + run-all.js 一键运行
├── tools/               # 像素贴图生成脚本（Python + Pillow）：鱼/物品/钓点图标裁剪与程序化生成
├── run.bat              # 启动后端（集成模式，9000，同时托管前端）
└── start-frontend.bat   # 启动前端独立静态服务器（5500）
```

## 数据存储

**运行时数据默认存放在用户「文档」目录**，与程序文件分离 —— 升级 / 覆盖安装不会丢存档：

```
Windows:  %USERPROFILE%\Documents\web-fishing-game\
macOS/Linux:  ~/Documents/web-fishing-game/   （无 Documents 时退回用户主目录）
```

目录内按域 + 按账号分文件，**每次上鱼只重写该账号一个文件**，市集/记录/经济/配置各自独立，互不干扰：

```
<文档>/web-fishing-game/
├── accounts/<账号>.json   # 身份(用户名/盐/密码哈希) + 金币 + 背包 + 钓竿配置 + 图鉴 + 累计渔获
├── market.json            # 开放市集挂单与序号
├── records.json           # 大鱼榜 / 小鱼纪录 / 前十大 / 前十小 / 全场最大
├── economy.json           # 商店供需乘数 / 价格历史 / 交易流水 / 市集成交
├── config.json            # 钓场配置 / 通知等级 / 上钩公式 / 双钓率 / 组件生成 / 鱼类体型 / 横幅队列 / 反馈规则
└── feedback.json          # 玩家反馈列表 + 每人下次可提交时间
```

- 可用环境变量 `FISHING_DATA_DIR` 覆盖数据目录（测试用临时目录即走此路径）。
- **旧数据自动搬迁**：首次启动时若文档目录尚无数据、而仓库内旧目录 `backend/data` 有数据，
  会整体拷贝到文档目录并打印 `[migrate] 数据目录已迁移到：…`；旧目录保留作备份，不再写入。
- 旧版单文件 `users.json` / `world.json` 也会在启动时幂等迁移为上述拆分结构。
- 数据目录已 gitignore（`data/` 与 `backend/data/`），含密码哈希与盐，绝不入库。

## 版本更新与前端缓存

前端 JS/CSS 会被浏览器缓存。为避免「服务器升级后，玩家浏览器里的旧前端请求到不兼容的新接口、
卡在进不去的页面」，实现了**版本守卫**：

- 版本号唯一定义在 `frontend/js/data.js` 的 `VERSION`（服务器与页面共用）。
- 服务器提供 `GET /api/version`（返回 `version` / `build`）。
- 页面启动时（`UI.init` 最先）比对本地 `VERSION` 与服务器版本，**不一致则带 `?v=&t=` 查询参数
  强制整页重载一次**，绕过 HTML/JS 缓存；用 `sessionStorage` 记录本次会话已刷新，
  避免服务器版本异常时无限刷新死循环。
- 服务器对静态资源始终返回 `Cache-Control: no-cache`，每次重载都会向服务器校验。

## 组件系统（v0.8 大改）

组件不再是「ID 即效果编码」，而是**底材 + 随机实例**：

- **底材（base）**：组件模板，定义部位、基准价与「可拥有词缀池」（每条词缀含数值区间），
  如竿身底材 `rod_bamboo`（竹制短竿）可拥有 `钓速 +8~+14` 与 `体型 -6~+4`。
- **品质（quality）**：普通 `common` / 稀有 `rare` / 史诗 `epic`，决定一件组件最多能带几条词缀
  （**1 / 2 / 3**），并给实例基准价倍率（1 / 1.5 / 2.4）。图鉴中「满词条」实例的品质显示为**金色**（仅背包/市集/装备弹窗；图鉴条目按品质正常显示，不再带满词条标记）。图鉴另有**「📍 钓点」分类**：每个钓点一张卡，点开可看该钓点能钓到什么与**实时产出概率**（与后台掉落池/增益/上鱼率配置一致，后台改动经 SSE 推送即时同步到打开中的详情）。
- **实例生成**：任何途径产出组件时，**先按品质权重定品质 → 再抽取 1 至「底材池长 ∩ 品质上限」条词缀
  → 最后逐条 roll 数值**。
- **实例身份 = 内容签名**：`底材#品质#词条码+数值,…`（词条款按底材池顺序规范化），
  如 `rod_bamboo#rare#spd+12,size-3`。词缀组合与数值完全相同的组件天然堆叠，背包仍是 `{签名: 数量}`。
- **修饰词**：由词缀组合推导（满词条且无负词条 → 完美的 等），**规则可在管理后台配置**（见下）。
- **图鉴**：按底材登记，展示该底材可拥有的**全部词缀与数值范围**；持有满词条实例时标注金色。点击卡片在**子窗口**查看详情。
  网格为**等高布局**（`grid-auto-rows: 1fr`），所有卡片对齐到最高的一张。
  产地取自服务器下发的钓场目录（连接时经 SSE `init` 同步），管理后台改过掉落池也会一致。
- **市集**：可按组件词条类型 + 数值区间筛选搜索；挂单行每条词缀后用括号标注该词缀的**数值范围**。
- 旧存档（v0.7 编码 id，如 `rod_spd15_size-5`）启动时自动升级为实例签名（选同部位中词缀类型覆盖最多的底材）。

### 组件生成配置（管理后台「🧩 组件生成」）

生成参数全部可调，保存即对全服生效（落盘 `config.json`，并随 `/api/version` 下发给前端）：

- **品质掉落概率**：普通 / 稀有 / 史诗的相对权重（默认 0.62 / 0.30 / 0.08）。
- **词条数量概率**：每个品质在「1 / 2 / 3 条」上的相对权重。
- **数值 roll 模型**：`linear` 均匀 / `normal` 正态（偏中值）/ `skew` 偏态（偏低值）。
- **底材词缀数值范围**：为任意底材的任意词缀覆盖最小~最大取值。
- **修饰词规则**：按顺序取第一条命中；条件含「满词条 / 无负词条 / 净收益区间 / 词条数区间」。
- 提供「试算 2 万次」预览品质分布与词缀均值；「恢复默认」一键还原。

## 宝匣合成（v0.10.2 · 沉船打捞）

侧边栏「🎁 宝匣合成」页：用「沉船宝匣残片」+ 金币合成宝匣，开箱获得组件实例。
四档梯度，**每一档消除一层随机**——这是这套系统的核心设计，不是四条并列的抽奖：

| 档位 | 残片 | 金币 | 基底 | 品质 | 词条数 | 消除了哪一层随机 |
|---|---|---|---|---|---|---|
| Ⅰ 沉船宝匣 | 8 | 8,000 | 随机 | 稀有 65% / 史诗 35% | ≥2 | 「1 词条垃圾」 |
| Ⅱ 深潜宝匣 | 20 | 30,000 | **自选部位** | 稀有 50% / 史诗 50% | ≥2 | 基底范围（29 选 1 → 4~5 选 1） |
| Ⅲ 深渊宝匣 | 45 | 90,000 | **自选底材** | 必定史诗 | **满池** `min(池长,3)` | 基底 + 品质 + 词条数 |
| Ⅳ 海王遗匣 | 100 | 300,000 | 自选底材 | **必定神话** | **4 条（50%）/ 3 条（50%）** | 词缀池边界 |

- **合成与开箱分两步**：合成产出的是**宝匣物品**（进背包），可囤积、可市集交易、可与玩家以物易物；
  开箱才产出组件。**宝匣不可卖给系统商店**（同整根钓竿，防止「市场买残片 → 合成 → 卖商店」的套利环）。
- **产出的组件可交易**，因此宝匣有真实的市场价格锚；残片来自落日海湾·礁石区（1.69%），
  钓竿的**「材料概率」词缀**能提高产出，后台「💰 经济参数 → 产出倍率 · 材料」是总闸门。
- **「部位」与「底材」的区别**：一个部位含 4~5 个底材（如竿身有竹制短竿/玻璃钢竿/碳素长竿/龙骨巨竿），
  且同部位不同底材是**取向差异而非强弱**（龙骨巨竿给大鱼/体型但**扣钓速**）。
  所以「自选部位」只是缩小范围、不保证取向，「自选底材」才完全确定——这是 Ⅱ 与 Ⅲ 档的分界。
- **神话品质（新增）**：`cap 4`、基准价倍率 3.6、**彩虹渐变**配色。**只能由宝匣产出**——
  后台「组件生成」的品质权重刻意不含 mythic，普通钓鱼掉落永远不会出神话件，否则宝匣的价值主张会被稀释。
- **突破件**：Ⅳ 档掷中 50% 时，词条数越过史诗的 3 条上限达到 4 条——池内优先填满、不足的部分用
  **池外词缀**补足（该底材词缀池里本没有的词缀，如给竿身补「双钓概率」）。
  池外词缀的数值区间**刻意明显弱于池内同类型**（如钓速 4~10 对照池内 8~38），且**恒为正**；
  否则 2 条池的弱底材补上强池外后会反超 4 条池底材，且终局件出减益词缀的体感太差。
  区间可在后台「🎁 宝匣配置」覆盖。
- **特例**：海王徽记是全游戏唯一的 4 条池底材，Ⅳ 档对它**必出满池 4 条、不掷骰、不补池外**——
  否则「未中」分支会把它 4 条池里弃掉 1 条，让最贵的宝匣产出降级件。它也是唯一能真正抽满池的底材
  （旧版 epic `cap=3` 让它永远抽不满，神话 `cap=4` 正好补上）。
- **突破保底**：后台「🎁 宝匣配置」可设 N——连续 N−1 次未突破则第 N 次必出（命中即清零，`0` = 关闭）。
  参考期望次数：关闭 2.00 / N=4 → 1.88 / **N=3 → 1.75（推荐）** / N=2 → 1.50。
  N=3 把最坏情况从「无上限」压到 3 次，期望成本只降 12.5%。保底进度在卡片与开箱子窗口都可见
  （保底不可见就等于没做），触发时提示「⚡ 保底触发」。
- 开箱产出**登记图鉴**（按底材累计）；**突破件全服横幅播报**（复用纪录轨）。
- 界面标识：神话件用彩虹字 + 独立的「突破」标签（优先于「满词条」金色，否则和满词条史诗长得一样）；
  池外词缀用**点线下划线**区分，开箱结果窗口另有 ★ 说明。
- 接口：`GET /api/chest`、`POST /api/chest/craft`、`POST /api/chest/open`、
  `POST /api/admin/settings`（`chestCfg.pityN`）、`POST /api/admin/component/config`（`extraAffixRanges`）。
  档位配方写在 `frontend/js/data.js` 的 `CHESTS`（与组件底材/词缀池同一份目录，前后端共用）。

## 架构要点（服务器权威）

- **钓鱼**：`POST /api/fishing/start|stop` 在服务器启停钓鱼循环；服务器定时器掷骰
  （含钓竿词缀加成），渔获入库/图鉴/大鱼榜/动态全部在服务端完成，经 SSE 定向推送
  `catch` 与权威 `assets`；断线自动停竿。客户端无法伪造渔获（旧 `/catch` 已删除）。
- **账号**：注册**必填 QQ 号**（5-12 位数字）与**确认密码**（两次一致）；`POST /api/login` 登录、
  `POST /api/logout` 登出（使该 token 失效；无其他会话时断开实时连接）。顶号：同账号二次登录使旧会话失效。
- **钓竿配置**：`POST /api/bd/set` 由服务器校验部位与组件目录并落盘；钓速变化即时
  重置进行中的循环。`/api/profile` 只接受显示名，客户端上报 coins/inventory 一律忽略。
  装备组件为**子页面（弹窗）**：点部位卡片的「装备组件」弹出该部位可选组件列表（筛选 / 排序 / 装备），
  不再占用配置页下方整块区域。负面词条（如 `-5% 钓速`）以**红色**显示。
  装备 = 从背包取用 1 件；卸下或换装时原样放回背包（不再摧毁，可循环取用）。
- **钓鱼页布局**：右侧只保留「渔场实况 + 我的渔获日志」，**不再内嵌背包**（背包见独立「背包」页）；
  左右两栏等高，渔获日志撑满右栏，底边与左栏对齐。
  有**钓点增益**的钓点按钮会加 **⚡ 标记**（鼠标悬停显示增益明细）；渔场动态页的钓场卡片也会标 ⚡。
  钓场目录在连接时经 SSE `init` 下发，并在进入游戏时主动拉取 `GET /api/grounds` 兜底，
  因此**后进入或刷新过的玩家同样能看到增益标记**。
- **切换钓点**：钓点选择用 `pointerdown` 触发（并用 `closest` 命中子元素）。上鱼广播会整页重绘，
  若用 `click` 则在按下与松开之间重绘会丢失事件，表现为「切换钓点被上鱼卡住」；键盘激活仍走 click 兜底。
- **近期渔获**：大鱼/稀有/组件入包时由服务器更新 presence 并广播。
- **体型加成**：钓竿「体型」词缀按百分比线性放大/缩小掷出的体型，**不设固定上限**
  （旧版曾硬性封顶 `上限×1.3`，导致高体型加成失效）。最小值保底 1cm。
- **双钓率**（v0.8.3 重做）：叠加值 A（百分比点数，50% 写作 A=50）→ 单次追加概率
  `P = A/(A+100) = 1 - 1/(1+A/100)`。判定：基础上钩 1 条；掷 < P 成功则额外 +1，
  再掷 < P 成功则再 +1；**最多 3 条**。概率分布：1 条 `1-P`、2 条 `P(1-P)`、3 条 `P²`；
  期望 `E = 1 + P + P²`。若世界配置了基础双钓率 B，则最终双钓概率 `1 - (1-B)(1-P)`
  （管理后台「公式管理」页可在 0–100% 调整 B，与上钩公式合并到同一页）。
- **渔获日志**：切换账号时会清空上一账号的渔获日志与临时状态（回归修复：曾残留串号）。
- **渔获记录**：大鱼 / 小鱼纪录按鱼种分卡片，**点击可看该鱼前十大 / 前十小**（`/api/records/top?id=&kind=big|small`）。
  两个榜单**每位玩家只保留一条最好成绩**（大鱼取其最大、小鱼取其最小），再排序取前 10。
  **全场最大纪录被破**时，服务器经 SSE `globalRecord` 广播，所有在线玩家网页顶部横幅滚动播报，
  **等整段字完整滚出屏幕后再收起**（按内容宽度动态定时，不再固定 5 秒硬关）。
- **横幅队列**：管理后台可发布多条滚动公告（内容 + 时长），玩家端**按队列顺序依次播放**；
  有内容且开启时**浏览器图标（favicon + 标题）闪烁**提示（标题可在管理页配置）。
  横幅显示时页面整体下移（`body.banner-open`），**不遮挡顶栏与内容**；开始新横幅会作废旧横幅的收尾回调，避免误取消。
- **系统商店**：出售数量由商店顶部控制条统一设定（加减按钮 + 手输），**对整个商店生效，直到下次被修改**；
  **两栏布局**：左侧商品网格，右侧「🤖 自动售出管理」栏（全部鱼规则 + 41 条鱼逐条列出规则状态与设置入口）；
  **筛选栏**（类别 / 仅显示我持有的 / 仅显示已设自动售出 / **排序：价格 / 涨幅 / 持有，再点同键反向排序**）；
  行情广播只刷新商品网格与右栏列表，**面板输入框不会被广播清空**；
  支持**自动售出**：可设「全部鱼」或单条鱼的规则——价格达到基准百分比、或绝对价格达到阈值时，
  背包里该鱼按系统行情自动卖出（钓到即卖；价格闲置回升越过阈值也会触发；可加**浮动接受值**
  允许在「阈值 − 浮动」提前成交，防止行情回落错过）。规则逐账号保存，鱼卡右上角 🤖 单独设置；
  钓竿配置：「命名当前钓竿」按钮移除（改名用槽位卡「改名」），「📥 收起」移到使用中槽位卡与「删除」并排
  （模块级状态，重绘与切页都保留）；每张商品卡按该数量显示「出售 N 个」。商店页**不再内嵌背包**（背包见独立页）。
- **背包 · 组件分类**：选中「🔧 组件」时按**词条组合 + 数值范围**分组展示——同底材、同品质、
  同词条类型集合的实例归为一组（组标题给出底材/品质/词条数/总数量），组内每个不同数值各占一行，
  并在每条词缀后括号标注该词缀的数值范围，便于比较取舍。
- **背包批量出售**：物品行的「批量出售」打开**子窗口**——可手填数量或用**滑块**调整，并显示**价格趋势图**
  与预估收入（替代旧版「全卖」直接确认）。
- **开放市集**：词条筛选下拉/数值输入获得焦点时会**暂停广播重绘**，避免筛选控件被刷新关闭；
  可按组件词条类型 + 数值区间筛选搜索；挂单组件每条词缀后括号标注数值范围。
- **统一子窗口**：前端不再使用浏览器原生 `confirm / prompt / alert`，所有确认与输入均改为站内**子窗口**。
- **宝匣**：合成与开箱全程服务端权威（掷骰、保底计数、图鉴登记、突破件播报均在服务端完成）。
  宝匣物品走 `kind: 'chest'`，自动获得独立背包分类与市集/以物易物支持；
  **系统商店明确拒收**（同整根钓竿），避免「市场买残片 → 合成 → 卖商店」的套利环。
  保底计数按 `rec.chestPity[档位id]` 存账号文件，命中即清零、随存档持久化；配置改动经 SSE `chestcfg` 同步。
- **管理后台**：`/api/admin/*` 需账号带 admin 标志；钓场/钓点配置覆盖落盘 `config.json`
  （`groundCfg`），启动时套用到共享目录，改动经 SSE `groundcfg` 即时同步所有在线客户端。
  **账号管理页**采用与账号授权一致的列表：可改密码 / 显示名 / 金币（`users/update`）、
  **查看并编辑资产快照**（金币与背包，`users/snapshot`）、**删除账号**（需二次确认 `users/delete`，不能删除自己）；
  改密会使其所有会话失效。**市集管理**支持关键字（物品/卖家/账号）+ 类型 + 词条/数值筛选，以及时间/价格/数量排序。
  **组件生成**页配置掉落参数（见上）。**宝匣配置**页设定突破保底次数与池外词缀区间。**公式管理**页集中上钩公式与双钓率。
  **横幅管理**页发布滚动公告并可管理队列与图标闪烁。
- **反馈意见**：`GET /api/feedback` 查 CD、`POST /api/feedback/submit` 提交（默认 24h CD）、
  `POST /api/feedback/skip` 花 10000 金币立即结束 CD；每条反馈带**状态标识**（已提交 / 已受理 / 已完成），
  玩家可见自己的状态，管理员在后台「反馈意见」页可逐条切换状态（`POST /api/admin/feedback/status`）；落盘 `feedback.json`。
- **版本**：`GET /api/version` 供前端缓存守卫比对。
- **测试辅助**：`FISHING_DEV=1` 环境变量开启 `/api/dev/seed|catch|rollsize|doublecount`（确定性回归用），
  正常部署不开启。

## 运行

### 集成模式（最简单）

```bat
run.bat
```

打开 http://localhost:9000 ，注册登录即可；多开浏览器标签 = 多真实玩家。

### 分离模式（前后端独立进程）

```bat
run.bat                 :: 窗口1：后端 API，http://localhost:9000
start-frontend.bat      :: 窗口2：前端静态服务器，http://localhost:5500
```

打开 http://localhost:5500 。前端 `API_BASE=auto` 会自动连接同主机的 9000 后端（后端已放行 CORS）。

前端也可以用任意其他静态服务器托管 `frontend/` 目录（nginx、GitHub Pages 等），或把
`frontend/js/config.js` 里的 `API_BASE` 改成显式地址（如 `https://api.example.com`）。

### 后端环境变量

| 变量 | 说明 |
|---|---|
| `PORT` | 监听端口，默认 9000 |
| `STATIC_DIR` | 指定前端目录；`none` 强制纯 API 模式（默认自动托管 `../frontend`，存在时） |
| `FISHING_DATA_DIR` | 数据目录覆盖（默认用户「文档」下的 `web-fishing-game`）；测试套件用临时目录隔离，避免清掉真实存档 |

## 测试

```bash
node tests/run-all.js   # 一键跑 e2e / auth-ui / fishing-interaction / bugfix / chest / ui-layout / admin / admin-ui
# 8 个套件并行执行（各套件端口与临时数据目录互不干扰），全量约 38 秒 / 1078 项
# admin-ui 是从 ui-layout 拆出的后台页面场景：只依赖「一个玩家页 + 一个后台页」，
# 与游戏侧场景无状态耦合，拆开后两者并行跑，全量墙钟不再被单个套件卡住
#   FISHING_TEST_JOBS=3        并行度（默认 = 套件数，上限 16）
#   FISHING_TEST_ONLY=admin,e2e 只跑指定套件
#   FISHING_TEST_SHARDS=ui-layout:2  把某套件拆成 N 个并行分片（套件需支持 FISHING_TEST_SHARD）
#   FISHING_TEST_TIMEOUT=480000 单套件超时兜底（ms）
```

测试内部不做固定 sleep：服务器就绪、页面渲染、弹窗出现等一律用 `tests/_util.js` 的
`waitHttp / waitFor` 轮询等待 + 超时，条件满足即刻继续（既快又不脆）。ui-layout 里另有
`untilGet / untilSel` 两个助手，用于替代「点一下 → sleep(1s) → 读接口/DOM 断言」的固定等待：
轮询到条件成立即返回（本地往返通常几十 ms），超时则返回最后一次取值，让断言仍报出真实失败信息。
**只有真正等时间的地方才保留固定等待**（如「等过一轮 5s 自动刷新」「等一个 >3s 的钓鱼周期」）。

`run-all.js` 只保留关键行与有界尾巴，不再整份缓存各套件日志；每个单元一结束就立刻打印小结并
带上墙钟时间戳，所以进度是实时的，不必等全部跑完。切后台页请用 `clickAdminNav(name, sel)`：
它按「导航项变 active + 关键控件就绪」判断，**不要用标题变化判断**——重复点同一页时标题不变，
会白等满超时。

jsdom / playwright-core 不随仓库分发，装好后放到项目 `node_modules`，或用
`NODE_PATH` / `FISHING_TEST_MODULES` 指定位置（`run-all.js` 也会自动使用项目同级的
`../fishing-test-modules/node_modules`）。ui-layout 需要真实 Chromium 内核浏览器：
优先 `CHROME_PATH`，否则自动探测 Chrome / Edge。测试启动前会自动清理同端口的残留旧实例
（Windows 下测试进程被强杀时可能留下孤儿服务器）。
