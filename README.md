# 钓鱼网站 v0.11.8（web-fishing-game）

零第三方依赖的多人联机网页钓鱼小游戏。**所有处理逻辑在服务端**：钓鱼循环、掷骰、词缀加成、
资产结算、钓竿配置均由后端权威执行；前端只发指令、收 SSE 广播、渲染。纯原生 Web 前端 +
Node 内置 `http` 模块后端，游戏数值目录前后端共用一份（UMD）。桌面与手机端各自设计排版
（手机端为底部标签栏 + 单栏内容），全站像素页游风格。

| 特性 | 说明 |
|---|---|
| 零依赖 | 运行时只用 Node 内置模块与原生浏览器 API，无需 `npm install` |
| 服务器权威 | 客户端无法伪造渔获与资产；前端不持账本 |
| 实时联机 | SSE 广播：在线玩家、渔场人数、渔获动态、行情、交易、横幅 |
| 数据目录 | 存档落在用户「文档」目录，按域 + 按账号拆分文件 |
| 可运营 | 管理后台 16 个页签，全部配置保存即生效并实时同步在线玩家 |
| 前端导航 | 14 个入口全部实现：钓鱼 / 钓竿配置 / 渔场动态 / 背包 / 宝匣合成 / 工坊 / 系统商店 / 开放市集 / 在线交易 / 商城 / 鱼类图鉴 / 渔获记录 / 反馈意见 / 日志 |

## 快速开始

需要 Node.js（任意较新版本；`run.bat` 会优先使用包内自带的 `node/node.exe`）。

### 集成模式（最简单）

```bat
run.bat
```

后端默认端口 9000，并自动托管 `frontend/`（存在时）。打开 <http://localhost:9000>，
注册登录即可；**多开浏览器标签 = 多真实玩家**。非 Windows 直接运行 `node backend/server.js`。

### 分离模式（前后端独立进程）

```bat
run.bat                 :: 窗口1：后端 API，http://localhost:9000
start-frontend.bat      :: 窗口2：前端静态服务器，http://localhost:5500
```

打开 <http://localhost:5500>。前端 `API_BASE=auto` 会自动连接同主机的 9000 后端
（后端已放行 CORS）。前端也可以用任意其他静态服务器托管 `frontend/` 目录
（nginx、GitHub Pages 等），或把 `frontend/js/config.js` 里的 `API_BASE` 改成显式地址。

### 管理后台

打开 `admin.html`（与游戏前端同源托管：集成模式 `:9000/admin.html`，分离模式 `:5500/admin.html`）。
使用游戏账号密码登录；**服务器上没有任何管理员时，第一个登录后台的账号自动成为管理员**
（引导机制），此后其他账号由管理员在「账号管理」页开关授权。

### 后端环境变量

| 变量 | 说明 |
|---|---|
| `PORT` | 监听端口，默认 9000（前端静态服务器 `frontend/serve.js` 默认 5500） |
| `STATIC_DIR` | 指定前端目录；`none` 强制纯 API 模式（默认自动托管 `../frontend`，存在时） |
| `FISHING_DATA_DIR` | 数据目录覆盖（默认用户「文档」下的 `web-fishing-game`）；测试套件用临时目录隔离 |
| `FISHING_DEV=1` | 开启 `/api/dev/seed\|catch\|rollsize\|doublecount` 测试辅助接口（正常部署不开启） |

## 数据存储

**运行时数据默认存放在用户「文档」目录**，与程序文件分离——升级 / 覆盖安装不会丢存档
（Windows: `%USERPROFILE%\Documents\web-fishing-game`；macOS/Linux: `~/Documents/web-fishing-game`，
无 Documents 时退回用户主目录）。目录内按域 + 按账号分文件，**每次上鱼只重写该账号一个文件**：

```
<文档>/web-fishing-game/
├── accounts/<账号>.json   # 身份(用户名/盐/密码哈希) + 金币 + 背包 + 钓竿配置/槽位 + 图鉴 + 累计渔获 + 自动售出规则
├── sessions.json          # 登录态（只存 token 的 SHA-256，30 天滑动过期；重启后登录态仍在）
├── market.json            # 开放市集挂单与序号
├── records.json           # 大鱼榜 / 小鱼纪录 / 前十大 / 前十小 / 全场最大
├── economy.json           # 商店供需乘数 / 价格历史 / 交易流水 / 市集成交 / 经济调参审计
├── config.json            # 钓场配置（含钓点地图坐标）/ 通知等级 / 上钩公式 / 双钓率 / 组件生成 /
│                          # 鱼类体型 / 宝匣保底与成本 / 工坊熔炼参数 / 商城商品与限购刷新时间 / 横幅队列 / 反馈规则
└── feedback.json          # 玩家反馈列表 + 每人下次可提交时间
```

- **旧数据自动搬迁**：首次启动时若文档目录尚无数据、而仓库内旧目录 `backend/data` 有数据，
  会整体拷贝到文档目录；旧版单文件 `users.json` / `world.json` 也会幂等迁移为上述拆分结构。
- 数据目录已 gitignore（`data/` 与 `backend/data/`），含密码哈希与盐，绝不入库。

## 架构要点

### 服务器权威

- **钓鱼循环**：`POST /api/fishing/start|stop` 在服务器启停定时器。每竿按抛竿间隔掷骰——
  上钩判断走后台公式，渔获从钓点掉落池按权重抽取（词缀/产出倍率加权），入库 / 图鉴 /
  大小纪录 / 全服动态全部在服务端完成后，经 SSE 定向推送 `catch` 与权威 `assets`。
  客户端无法伪造渔获（旧 `/catch` 已删除）。
- **会话**：注册必填 QQ 号（5–12 位数字）与确认密码；登录签发 token；同账号二次登录顶号
  （旧会话全部失效并断开实时连接）；登出使该 token 失效。会话落盘只存 token 的 SHA-256。
- **经济与市场**：出售 / 挂单 / 购买 / 交易 / 开箱 / 熔炼的掷骰与结算全部服务端完成，
  每次变动向当事人定向推送权威资产快照。

### 前端瘦客户端（分层）

```
config.js   API_BASE 配置（默认 'auto' 自动探测：同源 → 同主机 9000）
data.js     游戏数据目录（UMD：前端挂 window.GameData，后端 require 同一份）
engine.js   客户端状态层：展示状态 + 指令发送（无游戏逻辑）
net.js      网络层：指令 API + SSE 广播接收 + 版本守卫
ui.js       页面渲染与交互（14 个页面视图 + 子窗口 + 横幅 + 日志）
admin.js    管理后台页面逻辑（16 个页签）
```

- **就地更新**：上鱼、出售、行情变化等高频广播不再整页重建——钓鱼页按结构签名
  `fishingSig()` 判定后走 `patchFishingLive()` 只改变化的行；工坊 `wsPatchAssets()` 保留
  输入框焦点；背包 `patchInventoryRow()` 出售后不重排、不收起展开分组；任何主区输入框
  聚焦时广播只刷顶栏与导航（`mainInputFocused()`）。
- **统一子窗口**：全站不使用浏览器原生 `confirm / prompt / alert`，确认与输入均为站内子窗口。
- **悬空引用检测**：组件被熔炼/出售/交易消耗后，相关界面的选中项自动清空（`wsPruneStale()` 等）。
- **请求超时**：`fetch` 统一带 8 秒超时（`AbortController`），GET 自动重试一次，写操作不重试。
- **移动端**：`max-width: 640px` 单独排版——底部标签栏（适配安全区）、单栏内容、
  卡片两列网格、弹窗改为底部近全屏面板、表单字号 ≥16px 防 iOS 聚焦放大。
- **像素页游 UI**：`pixel.css` 主题层叠加在 `style.css` 之上（只改视觉不改逻辑）——
  融合像素字体（OFL，本地 woff2）+ RPG 九切片窗口框 + 世界地图版钓鱼页（右陆左海、
  浮漂节点、增益金框 ⚡、渔夫小人、飞鸟、动态水波）+ 全站程序化生成贴图（40 鱼 /
  材料 / 组件 / 钓点 / 导航图标，由 `tools/` 脚本生成，见下文）。

### 版本守卫与无感热更

前端 JS/CSS 会被浏览器缓存，服务器升级后旧前端会请求不兼容的新接口。版本号唯一定义在
`frontend/js/data.js` 的 `VERSION`，通过三条路径发现版本变化后**带 `?v=&t=` 查询参数强制
整页重载一次**（`sessionStorage` 防死循环）：

1. 页面启动时比对 `GET /api/version`；
2. SSE 重连后 `init` 带回新版本号（服务器重启必然断开 SSE，通常几秒内触发，最快）；
3. 兜底轮询（5 分钟）+ 标签页回到前台时补一次。

服务器对静态资源始终返回 `Cache-Control: no-cache`。配合服务端优雅热更
（见「管理后台 · 版本更新」），玩家全程无感。

### 健壮性兜底（v0.11.7）

服务端是所有玩家的**单点**：任何未捕获异常都会让 Node 进程直接退出，表现是「所有人在同一秒
掉线、且必须人工重启才恢复」。v0.11.7 起因一个畸形请求就能触发这种整体下线，现补三道防线：

- **请求体校验**：`JSON.parse('null')` 是**成功**的（返回 `null`），此前的解析代码只 catch 语法错误，
  于是紧随其后的 `d.token` / `d.username` 抛 `TypeError` 并把进程带走。现在统一走
  `bodyObj()`——只接受对象，`null` 与裸数字/字符串一律按「格式错误」返回 400。
  影响面原本覆盖 38 个 POST 端点（走 `auth()` 的 31 个 + 自行解析的 7 个）。
- **定时器自愈**：钓鱼循环（三处 `setInterval`）与市集过期清扫套上 `try/catch`，单次轮次抛错
  只记日志、下一竿照常继续，不再拖垮进程（此前只有限时钓场清扫包了保护）。
- **进程级兜底**：注册 `uncaughtException` / `unhandledRejection`，记录堆栈后**保持存活**——
  抛错的那一次操作会丢失（例如某一竿未结算），但其余玩家、在线连接与世界数据不受影响；
  取舍是「局部丢一次结算」优于「全服下线等重启」。

## 玩法系统

### 钓鱼与钓场

- **世界地图选点**：近岸地图（右陆左海）含 3 个常驻钓场（静水湖 / 急流河 / 落日海湾，
  各 3 钓点）+ 霜月冰湖活动场（锁定占位）；「出海」页签是未来钓场的航线预告。
  钓点是地图上的浮漂节点，带增益的钓点金框 + ⚡ + 数值常驻可见，点击直达。
- **钓速只影响抛竿间隔**：`间隔 = 基础间隔 ×(1 − 有效钓速/100) ×(1 − 钓点钓速增益/100)`，
  不低于最短间隔（默认基础 3000ms / 最短 800ms / 有效钓速上限 80%，后台可调）。
  有效钓速 = 词缀 + 全服加成（受上限截断）；钓点钓速增益为最终乘算。
- **上钩率由公式决定**：后台「公式管理」可编辑（递归下降解析，不用 eval），默认
  `clamp(90 + skill, 0, 100)`——没有技巧词缀时等价平值 90%。钓点可单独覆盖上鱼率与间隔。
- **双钓**：叠加值 A（50% 写作 A=50）→ 单次追加概率 `P = A/(A+100)`，连续判定最多 3 条；
  世界基础双钓率 B 合成为 `1 − (1−B)(1−P)`。
- **体型**：按 roll 模型（线性/正态默认/偏态）在鱼种基准区间取值，钓竿体型词缀按百分比
  放大/缩小且**不设固定上限**，最小保底 1cm。
- **重连自动续钓**：开始钓鱼 / 切换钓点时写入存档（`lastFishing`）；断线、顶号、服务器重启
  都不丢，重建 SSE 连接时服务端自动按原钓点续钓并在 `init` 里带回钓速明细。只有玩家主动
  收竿才清除；续钓前校验钓点存在与钓场开放状态。
- **掉落档 ≠ 品质**：`FISH.common/big/rare` 三个数组是掉落档（决定掉落池分组与后台产出倍率
  的作用范围），40 种渔获的品质另按价值归入普通/稀有/史诗。
- **渔场实况场景（v0.11.8）**：右栏顶部的垂钓小场景里，游鱼取自**当前钓点的掉落池**（不在钓点
  时取当前所选钓场的全部钓点），按掉落权重随机、按鱼种体型缩放，游动方向与朝向一致；每隔几秒
  把游到画面边上的一条换成池里的另一种鱼。掉落池/钓点变化时（含后台改配置的 `groundcfg` 推送）
  整批重掷，所以画面始终跟着你所在钓场走。

### 品质与组件

全站品质只有四种：**普通 / 稀有 / 史诗 / 神话**（渔获与组件共用命名与配色；「大鱼」不是品质）。
神话只能由宝匣产出——后台掉落权重刻意不含 mythic。

- **组件模型**：组件 = 底材 + 品质 + 随机词条实例。**29 种底材 × 6 类词缀**
  （钓速 / 技巧 / 稀有概率 / 材料概率 / 体型 / 双钓概率），每条词缀带底材专属数值区间，
  含正负取舍（负词条红色显示）。品质决定词条上限（1/2/3/4）与基准价倍率（1/1.5/2.4/3.6）。
- **实例身份 = 内容签名**：`底材#品质#词条码+数值,…`（词条按底材池顺序规范化），如
  `rod_bamboo#rare#spd+12,size-3`。词缀组合与数值完全相同的组件天然堆叠。
- **生成流程**：先按品质权重定品质 → 抽 1 至「底材池长 ∩ 品质上限」条词缀 → 逐条 roll 数值
  （roll 模型：linear 均匀 / normal 正态 / skew 偏态；roll 到 0 拒绝并重 roll 一次）。
- **修饰词**：由词缀组合推导（满词条且无负词条 → 完美的 等），规则可在后台配置。
- **钓竿词缀「技巧」**：v0.11 起是上钩率公式里的变量 `skill`（替代旧的「大鱼概率」词缀）；
  钓点增益仍保留「大鱼概率」这一类（共 7 类增益）。
- **图鉴**：按底材登记，展示该底材全部词缀与数值范围；另有「📍 钓点」分类，点开看该钓点
  能钓到什么与实时产出概率。持有满词条实例时背包/市集/装备弹窗标金色。
- **组件订阅提醒**：设置底材/品质/词条/数值条件，命中时背包红标、浏览器图标闪烁并写入日志。
- **物品简介（v0.11.8）**：背包里的**渔获 / 材料 / 宝匣**鼠标悬停即有浮标（图片 + 品质 + 现价 +
  持有量 + 一句话用途），点一下开完整简介子窗口：图片、一句话简介、**🧭 用途**（按类型给实际机制：
  渔获=出售/挂单/记录，材料=熔炼投料对应词缀与宝匣·重铸用途，宝匣=开箱消耗与产出品质）与
  **📍 产出地点**（宝匣换成「📦 来源」）。文案全部由机制与当前后台配置现算（宝匣用配置里的 desc、
  熔炼数值读实时配置），不另写死一份说明。组件仍走原有的「属性」窗口。
- **旧存档兼容**：v0.7 编码 id 与旧短码（`big`）在启动迁移时自动升级为规范实例签名。

### 钓竿配置与存档

- 7 个部位（竿身/线组/钩/饵/卷线器/配件/饰品栏位），装备组件走**子页面弹窗**
  （筛选/排序/装备），装备 = 从背包取用 1 件，卸下或换装原样放回背包。
- `POST /api/bd/set` 由服务器校验部位与组件目录并落盘；钓速变化即时重置进行中的循环。
- **钓竿槽位**：上限 8 根，第 1 个免费，之后按 1w/5w/10w/20w/40w/80w/160w 金币购买。
  可命名、收起保存、一键切换；**已保存钓竿的配件被锁定**（不可单独出售/上架/以物易物，
  背包与交易里显示 🔒），但**整根钓竿可在市集出售**（市集「🎣 钓竿」分类，逐件词条展示）。

### 宝匣合成（沉船打捞）

用「沉船宝匣残片」+ 金币合成宝匣，开箱产出组件实例。四档梯度，**每一档消除一层随机**：

| 档位 | 残片 | 金币 | 基底 | 品质 | 词条数 | 消除了哪层随机 |
|---|---|---|---|---|---|---|
| Ⅰ 沉船宝匣 | 8 | 8,000 | 随机 | 稀有 65% / 史诗 35% | ≥2 | 「1 词条垃圾」 |
| Ⅱ 深潜宝匣 | 20 | 30,000 | **自选部位** | 稀有 50% / 史诗 50% | ≥2 | 基底范围（29→4~5 选 1） |
| Ⅲ 深渊宝匣 | 45 | 90,000 | **自选底材** | 必定史诗 | **满池** | 基底 + 品质 + 词条数 |
| Ⅳ 海王遗匣 | 100 | 300,000 | 自选底材 | **必定神话** | 4 条(50%) / 3 条(50%) | 词缀池边界 |

- 合成与开箱分两步：合成产出**宝匣物品**（进背包，可囤积、可市集交易、可以物易物），
  开箱才产出组件。**宝匣与整根钓竿都不可卖给系统商店**（防「市场买残片 → 合成 → 卖商店」套利环）。
- **突破件**：Ⅳ 档掷中 50% 时词条数越过史诗上限达到 4 条，池内优先填满、不足部分用
  **池外词缀**补足（该底材本没有的词缀，数值区间刻意弱于池内且恒为正，界面标 ★）。
- **边界取值**：突破件与投入龙宫宝珠的熔炼，每个数值掷两次取**离区间边界更近**的那次
  （极值更易出现）。
- **突破保底**：后台可设 N——连续 N−1 次未突破则第 N 次必出（`0` = 关闭，推荐 N=3），
  保底进度在卡片与开箱窗口可见。
- **成本可配**：后台「🎁 宝匣配置」可改四档成本（残片/金币），保存即同步玩家端与合成校验；
  **池外词缀数值区间**也在此配置（`componentCfg.extraAffixRanges`），并同步决定工坊补缀取值。
- 残片来自落日海湾·礁石区掉落，钓竿「材料概率」词缀可提高产出。

### 工坊 · 熔炼与重铸

**熔炼**（「⚒ 工坊」页签一）：放两件**同部位**组件（主件保留、副件熔毁），各选一条词条，
熔炼后主件的词条就是这两条并重新 roll 数值——是除宝匣之外唯一能跨出词缀池边界的途径。

| 规则 | 默认 | 说明 |
|---|---|---|
| 副件连区间一起提供 | 开 | 副件搬来的词缀按**副件自己的底材区间**取值（好底材当副件，强区间一起带过来） |
| 补缀不受底材池限制 | 开 | 投料可补**全部 6 类词缀**里结果尚未拥有的词缀（界面上标 ★ 池外） |
| 补缀后词条数上限 | 3 | 主 + 副 + 补缀，可越过品质上限与底材池长（后台可收 1~6，1 = 禁止补缀） |
| 补缀按池外区间取值 | 开 | 与宝匣突破件共用同一份区间配置，后台改一处两边同时生效 |

- **投料**：材料即「词缀定向器」，投料份数最多的材料决定要补的词缀；投得越多补缀成功率
  越高、金币花费越高。**龙宫宝珠**（可选，一次至多 1 个）：roll 改为掷两次取边界值。
  **投料区按上面选定的两条词条过滤（v0.11.8）**：只列出「对应词缀还不在熔炼结果里」的材料
  ——判据与服务端校验共用 `smeltAddableAffixes` + 补缀上限，所以列出来的就一定能投；两条词条
  没选完时先全列（规则未定）。被过滤掉的材料若已填过份数会一并清零，不会留下「看不见却仍在投」
  的份数。词条胶囊选中后**整块填充高亮**（负值词条红色填充），一眼能看出主副各选了哪条。
- **残片保留**（可选）：主件是海王遗匣产出的神话件（带池外词缀）时，可另投至多 10 片残片
  （**不计入投料**、不改成功率与花费），成功时按每片 10% 把主件的池外词缀**按原值**保留。
- **成功率与花费**：默认基础成功率 50%、每份材料降低失败率 2 个百分点、补缀成功率 =
  投料份数 × 8%（上限 95%）；金币 = 基础 5000 + 每份 900 + 宝珠 20000。全部后台可调。
- **失败结算**：副件、投料、残片熔毁，金币照扣，且**主件被熔掉选中的那条词条**
  （其余词条与品质原值保留退回背包；只有一条词条的主件变成 0 词条底材本体，不会被销毁）。
- **材料对应表**：

  | 材料 | 品质 | 对应词缀 |
  |---|---|---|
  | 反光假饵 | 普通 | 技巧 |
  | 诱饵包 | 普通 | 稀有概率 |
  | 耐磨绳 | 普通 | 体型 |
  | 沉船宝匣残片 | 稀有 | 材料概率（另有「残片保留 / 重铸」两种用法） |
  | 潮汐砂 | 稀有 | 钓速 |
  | 龙鳞碎屑 | 史诗 | 双钓 |
  | 龙宫宝珠 | 史诗 | 催化剂（不指向词缀） |

**重铸**（页签二）：放一件**宝匣产出的神话组件**，用沉船宝匣残片（默认 10 片 + 0 金币）
把全部词条的数值重新掷一遍——类型与条数不变，只洗数值。不会失败；可选开关「至少不比原来差」。
神话品质就是「宝匣产出」的身份判据（全游戏只有海王遗匣产出神话件，熔炼保留品质）。
熔炼预览逐条列出结果词缀的区间来源与具体区间，四项规则全部可在后台「⚒ 工坊配置」调整，
全部关掉即退回 v0.11.4 口径。

### 经济系统

- **系统商店**（单乘数供需模型）：每件经济物品（渔获/材料）维护一个价格乘数
  `m ∈ [地板, 天花板]`（默认 40%~200%），实际价 = 基准价 × m。售出时 m 按比例下压
  （默认每件 ÷(1+0.0075)，约 -0.7%/件），闲置时以时间常数（默认 60 分钟）向目标价
  （默认 200%）指数回升。组件为固定价道具，不走供需。可查价格走势图与交易流水。
  **自动售出**：可设「全部鱼」或单鱼规则——基准价百分比线或绝对价格线任一达到即卖
  （钓到即卖、闲置回升越线也触发），支持**浮动接受值**提前成交；规则逐账号保存。
- **开放市集**：玩家挂单交易。每人最多 40 单；时长 6/12/24 小时对应上架费 1%/3%/5%
  （下架不退），成交收 10% 交易税（卖家承担）；支持部分购买、整根钓竿与宝匣交易。
  可按组件词条类型 + 数值区间筛选搜索；右栏「我的背包」支持多选一键上架。
- **在线交易**：以物易物、双确认、0% 税。任何一方改动物品 → 双方确认重置 + 3 秒冷却；
  交易期间背包列表锁定，掉线自动取消。
- **商城**（每日限购）：金币直购官方商品（默认售熔炼材料），每件可设**每日限购**，
  按后台设定的刷新时间（默认 04:00）划分周期、跨点惰性重置。商品/价格/限购全部后台配置。

### 记录、横幅与社交

- **渔获记录**：大鱼/小鱼纪录按鱼种分卡片，点击看该鱼**前十大/前十小**（每位玩家每榜
  只留一条最好成绩）；全场最大纪录置顶（贴图缩放/偏移后台可调）。**任一榜单更新都会
  经 SSE 在顶部横幅播报**（覆盖所有鱼种，按内容宽度滚完整段再收起）。
- **横幅三条独立轨道**：版本更新轨（服务端升级倒计时，最高优先级）· 纪录轨（排队播放）
  · 公告轨（管理后台发布，可自定义颜色/队列管理/停止滚播/查看实时观看人数）。
  横幅显示时页面整体下移不遮挡内容；有公告时浏览器图标与标题闪烁（可配置）。
- **全服动态通知等级**：`all` / `uncommon`（仅非普通渔获）/ `offrange`（仅体型越界）/
  `records`（仅破纪录）/ `none`，只影响广播，钓者自己的推送不受影响。
- **反馈意见**：类型（Bug/建议/平衡/其他）+ 内容提交，默认 24 小时 CD、可花金币
  （默认 10000）立即结束；每条带状态标识（已提交/已受理/已完成），管理员可逐条切换并
  **发放金币奖励**（实时到账 + 站内通知）。CD 与费用后台可配。
- **日志页**：分列记录 🐟 渔获 / 🖥 系统 / ✅ 交易 / 🏆 纪录 / 🔔 订阅提醒，
  按类型筛选，本地按账号保留 300 条。

## 测试

```bash
node tests/run-all.js
```

9 个套件并行执行（各套件独立端口与临时数据目录，互不干扰）：
**e2e**（全量功能端到端）· **auth-ui**（账号/会话）· **fishing-interaction**（真实浏览器交互）
· **bugfix** · **chest**（宝匣）· **v011**（品质/技巧/熔炼/商城/热更等 v0.11 全量功能）
· **ui-layout**（像素 UI 布局）· **admin**（后台功能）· **admin-ui**（后台页面场景）。

- 套件内部不做固定 sleep：用 `tests/_util.js` 的 `waitHttp / waitFor` 轮询等待，条件满足即继续；
  只有真正等时间的地方（自动刷新周期、钓鱼周期）才保留固定等待。
- 环境变量：`FISHING_TEST_JOBS`（并行度）、`FISHING_TEST_ONLY=e2e,admin`（只跑指定套件）、
  `FISHING_TEST_SHARDS=ui-layout:2`（套件分片）、`FISHING_TEST_TIMEOUT`（单套件超时 ms）。
- **测试依赖不随仓库分发**：jsdom / playwright-core 需自行安装到项目 `node_modules`，
  或用 `NODE_PATH` / `FISHING_TEST_MODULES` 指定位置（`run-all.js` 也会自动使用项目同级的
  `../fishing-test-modules/node_modules`）。ui-layout 需要真实 Chromium 内核浏览器：
  优先 `CHROME_PATH`，否则自动探测 Chrome / Edge。
- `tests/shots*.js` 与 `tests/shots/` 是界面截图脚本与产物（截图不入库，可随时重新生成）。
