# 钓鱼网站 v0.8.0（服务器权威 · 前后端分离）

零第三方依赖的多人联机网页钓鱼小游戏。**所有处理逻辑在服务端**：钓鱼循环、掷骰、
词缀加成、资产结算、钓竿配置均由后端权威执行；前端只发指令、收 SSE 广播、渲染。
纯原生 Web 前端 + Node 内置 `http` 模块后端，游戏数值目录前后端共用一份（UMD）。
桌面与手机端各自设计排版（手机端为底部标签栏 + 单栏内容）。

## 项目结构

```
├── backend/
│   └── server.js        # 权威服务器：钓鱼循环/掷骰/钓竿配置/账号/商店/市集/交易/SSE 广播
│                        # 数据落盘 backend/data/（按域 + 按账号拆分，见下）；游戏目录 require 自 frontend/js/data.js
├── frontend/            # 纯静态瘦客户端，可部署到任意静态服务器
│   ├── index.html
│   ├── admin.html       # 管理后台页面（管理员账号登录，见「管理后台」章节）
│   ├── serve.js         # 本地开发用静态服务器（零依赖）
│   ├── css/style.css
│   ├── css/admin.css
│   └── js/
│       ├── config.js    # API_BASE 配置（默认 'auto' 自动探测）
│       ├── data.js      # 游戏数据目录（UMD：前端挂 window.GameData，后端 require）
│       ├── engine.js    # 客户端状态层：展示状态 + 指令发送（无游戏逻辑）
│       ├── net.js       # 网络层：指令 API + SSE 广播接收
│       ├── admin.js     # 管理后台页面逻辑
│       └── ui.js        # 页面渲染与交互
├── tests/               # 6 个测试套件 + run-all.js 一键运行
├── run.bat              # 启动后端（集成模式，9000，同时托管前端）
└── start-frontend.bat   # 启动前端独立静态服务器（5500）
```

## 数据存储（v0.8 拆分）

按域 + 按账号分文件，**每次上鱼只重写该账号一个文件**，市集/记录/经济/配置各自独立，互不干扰：

```
backend/data/
├── accounts/<账号>.json   # 身份(用户名/盐/密码哈希) + 金币 + 背包 + 钓竿配置 + 图鉴 + 累计渔获
├── market.json            # 开放市集挂单与序号
├── records.json           # 大鱼榜 / 小鱼纪录 / 前十大
├── economy.json           # 商店供需乘数 / 价格历史 / 交易流水 / 市集成交
├── config.json            # 钓场钓点覆盖配置 / 通知等级 / 上钩公式
└── feedback.json          # 玩家反馈列表 + 每人下次可提交时间
```

`data/` 已 gitignore（含密码哈希与盐，绝不入库）。首次启动若检测到旧版
`data/users.json`、`data/world.json`，会自动迁移到上述结构并打印 `[migrate]` 日志；
迁移是幂等的，旧文件保留但不再写入。

## 版本更新与前端缓存

前端 JS/CSS 会被浏览器缓存。为避免「服务器升级后，玩家浏览器里的旧前端请求到不兼容的新接口、
卡在进不去的页面」，实现了**版本守卫**：

- 版本号唯一定义在 `frontend/js/data.js` 的 `VERSION`（服务器与页面共用）。
- 服务器提供 `GET /api/version`（返回 `version` / `build`）。
- 页面启动时（`UI.init` 最先）比对本地 `VERSION` 与服务器版本，**不一致则带 `?v=&t=` 查询参数
  强制整页重载一次**，绕过 HTML/JS 缓存；用 `sessionStorage` 记录本次会话已刷新，
  避免服务器版本异常时无限刷新死循环。
- 服务器对静态资源始终返回 `Cache-Control: no-cache`，每次重载都会向服务器校验。

## 反馈意见

侧边栏「📮 反馈意见」页：选择类型（Bug / 建议 / 平衡 / 其他）填写并提交。

- **默认每人每 24 小时可提交 1 条**（服务器权威，按账号记录下次可提交时间）。
- 冷却中可**花 10000 金币立即结束 CD**，随后即可再次提交。
- 玩家只能看到自己的历史反馈；管理员在后台「📮 反馈意见」页查看全部（只读，含提交者与版本）。
- 接口：`GET /api/feedback`、`POST /api/feedback/submit`、`POST /api/feedback/skip`、
  `GET /api/admin/feedback`。

## 手机端适配

手机端（`max-width: 640px`）**单独设计排版**，不是简单压缩桌面布局：

- **底部标签栏**：侧边导航转为固定底部标签栏（图标在上、文字在下），适配刘海屏安全区，
  拇指可达；桌面端仍为左侧竖排导航。
- **单栏内容**：内容区单栏、内边距收紧；顶栏紧凑并隐藏占地较大的「位置」信息。
- **组件化重排**：钓竿配置/图鉴/记录/商店卡片改两列网格；背包行、市集行的名称与操作按钮换行；
  交易双方栏上下堆叠；弹窗改为底部弹出的近全屏面板。
- **触控优化**：按钮与钓点按钮加大点击区域；表单控件字号 ≥16px，避免 iOS 聚焦自动放大。
- 管理后台（`admin.css`）同样有独立的手机端底部标签栏布局。

## 组件系统（v0.8 大改）

组件不再是「ID 即效果编码」，而是**底材 + 随机实例**：

- **底材（base）**：组件模板，定义部位、基准价与「可拥有词缀池」（每条词缀含数值区间），
  如竿身底材 `rod_bamboo`（竹制短竿）可拥有 `钓速 +8~+14` 与 `体型 -6~+4`。
- **品质（quality）**：普通 `common` / 稀有 `rare` / 史诗 `epic`，决定一件组件最多能带几条词缀
  （**1 / 2 / 3**），并给实例基准价倍率（1 / 1.5 / 2.4）。图鉴中「满词条」实例的品质显示为**金色**。
- **实例生成**：任何途径产出组件时，**先按品质权重定品质 → 再抽取 1 至「底材池长 ∩ 品质上限」条词缀
  → 最后逐条 roll 数值**。
- **实例身份 = 内容签名**：`底材#品质#词条码+数值,…`（词条款按底材池顺序规范化），
  如 `rod_bamboo#rare#spd+12,size-3`。词缀组合与数值完全相同的组件天然堆叠，背包仍是 `{签名: 数量}`。
- **修饰词**：由词缀组合推导，如「完美的 竹制短竿」（满词条且无负词条）/「精良的」「平衡的」「粗糙的」。
- **图鉴**：按底材登记，展示该底材可拥有的**全部词缀与数值范围**；持有满词条实例时标注金色。
- **市集**：可按组件词条类型 + 数值区间筛选搜索。
- 旧存档（v0.7 编码 id，如 `rod_spd15_size-5`）启动时自动升级为实例签名（选同部位中词缀类型覆盖最多的底材）。

## 架构要点（服务器权威）

- **钓鱼**：`POST /api/fishing/start|stop` 在服务器启停钓鱼循环；服务器定时器掷骰
  （含钓竿词缀加成），渔获入库/图鉴/大鱼榜/动态全部在服务端完成，经 SSE 定向推送
  `catch` 与权威 `assets`；断线自动停竿。客户端无法伪造渔获（旧 `/catch` 已删除）。
- **钓竿配置**：`POST /api/bd/set` 由服务器校验部位与组件目录并落盘；钓速变化即时
  重置进行中的循环。`/api/profile` 只接受显示名，客户端上报 coins/inventory 一律忽略。
- **近期渔获**：大鱼/稀有/组件入包时由服务器更新 presence 并广播。
- **体型加成**：钓竿「体型」词缀按百分比线性放大/缩小掷出的体型，**不设固定上限**
  （旧版曾硬性封顶 `上限×1.3`，导致高体型加成失效）。最小值保底 1cm。
- **管理后台**：`/api/admin/*` 需账号带 admin 标志；钓场/钓点配置覆盖落盘 `config.json`
  （`groundCfg`），启动时套用到共享目录，改动经 SSE `groundcfg` 即时同步所有在线客户端。
- **反馈意见**：`GET /api/feedback` 查 CD、`POST /api/feedback/submit` 提交（默认 24h CD）、
  `POST /api/feedback/skip` 花 10000 金币立即结束 CD；落盘 `feedback.json`。
- **版本**：`GET /api/version` 供前端缓存守卫比对。
- **测试辅助**：`FISHING_DEV=1` 环境变量开启 `/api/dev/seed|catch|rollsize`（确定性回归用），
  正常部署不开启。

## 运行

### 集成模式（最简单）

```bat
run.bat
```

打开 http://localhost:9000 ，注册登录即可；多开浏览器标签 = 多真实玩家。

### 分离模式（前后端独立进程）

```bat
run.bat                 :: 窗口1：后端 API，http://localhost:9000
start-frontend.bat      :: 窗口2：前端静态服务器，http://localhost:5500
```

打开 http://localhost:5500 。前端 `API_BASE=auto` 会自动连接同主机的 9000 后端（后端已放行 CORS）。

前端也可以用任意其他静态服务器托管 `frontend/` 目录（nginx、GitHub Pages 等），或把
`frontend/js/config.js` 里的 `API_BASE` 改成显式地址（如 `https://api.example.com`）。

### 后端环境变量

| 变量 | 说明 |
|---|---|
| `PORT` | 监听端口，默认 9000 |
| `STATIC_DIR` | 指定前端目录；`none` 强制纯 API 模式（默认自动托管 `../frontend`，存在时） |
| `FISHING_DATA_DIR` | 数据目录覆盖（默认 `backend/data`）；测试套件用临时目录隔离，避免清掉真实存档 |

## 管理后台

打开 `admin.html`（与游戏前端同源托管）：

- 分离模式：http://localhost:5500/admin.html （前端在 5500 时）
- 集成模式：http://localhost:9000/admin.html （run.bat 单进程时）

**登录与授权**：使用游戏账号密码登录；账号须带管理员标志。服务器上没有任何管理员时，
**第一个登录管理后台的账号自动成为管理员**（引导机制）。此后其他账号由管理员在
「账号授权」页开启/关闭（管理员不能撤销自己的权限）。获得权限的玩家在游戏侧边栏会看到
「🛡 管理后台」入口。

**功能**：

| 页签 | 说明 |
|---|---|
| 概览 | 在线/钓鱼人数、账号数、挂单数、当前通知等级与公式（5 秒自动刷新） |
| 账号授权 | 全部账号列表，开关「管理员」权限 |
| 渔场钓点 | 编辑每个钓点的掉落池（鱼/材料/组件 + 权重，**实时百分比显示**）、钓点增益（6 类词缀 + 数值，可与钓竿词缀叠加，保存即时生效并重启受影响的钓鱼循环）、钓场一键锁定/解锁（锁定立即停竿） |
| 市集管理 | 全部挂单一览，「退回」将物品退回卖家背包（上架费不退，与过期规则一致） |
| 上钩公式 | 编辑每次抛竿的上钩概率公式（安全解析不用 eval；变量 `speed/big/rare/material/size/double/interval`，函数 `min/max/floor/ceil/round/abs/clamp`），支持校验与试算 |
| 通知等级 | 控制全服动态推送范围：`all` 全部 / `uncommon` 仅非普通 / `offrange` 仅体型超出基准范围 / `records` 仅破纪录 / `none` 关闭；钓者自己的渔获推送不受影响 |
| 反馈意见 | 全部玩家反馈列表（只读，含类型/提交者/时间/版本），按时间倒序 |

所有配置修改**保存即生效**，无需重启；掉落池/增益/锁定/公式/通知等级持久化到 `backend/data/config.json`。
