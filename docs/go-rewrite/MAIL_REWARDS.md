# 奖励邮件

## 操作与范围

后台「邮件管理」复用现有管理员认证、物品目录、资产事务和审计。流程为选择收件人、配置邮件与附件、生成准确预览、确认投递。支持全服、游戏活跃 / 严格游戏登录、注册区间、UID / 账号 / 昵称搜索、本页选择、跨页选择全部结果并排除部分玩家、粘贴指定名单。默认排除封禁和管理员账号。

时间按北京时间填写，区间为起点包含、终点不包含。活跃口径包含正常游戏请求、登录和有效长连接；严格登录仅记录成功的游戏登录，后台登录不算。历史覆盖起点在搜索结果中明确显示，上线前未采集的历史不能据此还原，需用已核实的指定名单补充。

预览将奖励和收件人持久化冻结，后续注册的玩家不进入既有批次。最多 50,000 名收件人；手工名单与排除名单合计最多 2,000 项。附件最多 30 项，每项每人最多 1,000,000 件，装备实例总计最多 100 件。支持物品搜索、多选、鱼类普通 / 大型 / 巨型、组件品质和词条。

默认领取期限为每封实际投递后 30 天，也可永久。草稿 / 模板载入时创建新草稿并重新生成名单；发放记录可查看逐人结果、暂停 / 继续、重试失败项、撤回未领取附件。投递每秒处理最多 50 人，关闭浏览器不影响后台队列；服务重启继续处理。异常收件人独立回滚并记为失败，成功收件人不会被重新投递。撤回和领取按邮件行锁串行，已领取的奖励不扣回。

## 绑定语义

新邮件原始附件始终账号绑定：禁止系统出售、自动出售、市场上架和玩家转移，允许消耗。货币不进入物品绑定体系。

管理员逐项设置「直接产物绑定 / 不绑定」，默认绑定。消耗优先使用要求继承绑定的库存，再用不要求继承的绑定库存，最后普通库存；任一实际消耗的输入要求继承，直接产物即绑定且继续继承。装备成长 / 工坊 / 宝箱可选择仅用普通输入，服务端检查可用量，无法借此解除绑定规则。装备正常使用、钓鱼与远航收益按既有规则。

库存仍保留原有总量字段，bound_quantity 是总量子集，inherit_quantity 是其中要求产物继承的子集，三者由数据库约束保护。装备使用实例字段保存对应规则；资产总账追加绑定结果记录。已有历史附件和既有库存维持历史规则，不追溯识别已领取旧奖励。管理快照保存 / 恢复绑定子集和配装组件信息。

## 接口复用与运行

- GET /api/admin/mail 保留物品目录和玩家邮箱查询；view=recipients、batches、batch-recipients 扩展查询。
- POST /api/admin/mail/send 保留个人发信；batch=1 支持 draft、preview、send、pause、resume、retry、revoke。命令复用 requestKey 幂等，批次操作检查 revision 防止过时页面重复操作。
- GET /api/mail 支持 unread、pending、expiring 筛选。
- POST /api/mail/claim 的 id=all 按 afterId 游标每次处理最多 50 封，逐封原子领取并返回失败清单；同一封不会重复到账。
- /api/me、资产 SSE 和相关资产回包增加 rewardBindings；现有库存读取保持兼容。

数据库迁移为 0033_mail_rewards.sql，在 main 的 0032_gear_growth.sql 后追加；保留新装备自身的成长绑定规则，奖励绑定与之分别判定。

迁移仍是显式运维步骤，运行中的游戏不会自行执行 DDL。应用账号需使用更新后的 tools/go-rewrite/postgres-runtime-grants.sql 授权。复用既有管理员权限，本次没有新增运营岗位 / 双人审批体系。未来人员增加时可再引入分级审批和额度控制。

## 验证

完整测试只执行一轮，失败修复和后续合并仅按影响范围复测。使用隔离 PostgreSQL 合成账号，浏览器回归使用模拟接口，不投递真实奖励。验证记录见同目录 MAIL_REWARDS_VALIDATION.md。
