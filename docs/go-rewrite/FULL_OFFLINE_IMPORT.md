# 完整旧服备份导入

`cmd/import-offline` 面向经过审核的旧 Node 分段存档，使用全新的候选 PostgreSQL 数据库。它与早期 `cmd/import-legacy` 合成演练入口分开；不能把任何一个入口直接指向正在运营的数据库。

准备工具 `tools/go-rewrite/prepare-real-snapshot.py` 只复制离线文件并用 SQLite 标准接口导出 Wiki，不执行备份中的代码。它检查重复 JSON 键、SQLite 完整性和外键，并记录每个文件的字节数与 SHA256。输出包含密码哈希、MFA 和历史记录，必须放在 Git 忽略且受控的目录。

```powershell
python tools/go-rewrite/prepare-real-snapshot.py --source <离线存档目录> --destination <新的受控副本目录>
# 通过环境变量配置候选库与目标服务的 MFA 密钥，不将密钥写入命令行。
# FISHING_GO_MIGRATION_DATABASE_URL / FISHING_GO_MFA_KEY
go -C server-go run ./cmd/migrate up
go -C server-go run ./cmd/import-offline --snapshot <受控副本目录> --source-version <已核对的来源声明> --output <新的私有报告>
go -C server-go run ./cmd/import-offline --reconcile --snapshot <受控副本目录> --source-version <相同来源声明> --output <另一个新的私有报告>
```

导入前检查候选库没有账号、迁移记录或已有业务元数据。目录、账号、资产、恢复钓鱼偏好、配置、市场经济、历史世界数据及 Wiki 在同一数据库事务内写入并逐域核对。失败时整个事务回滚，原因只记录在私有报告；不会留下可被误判为成功的半套用户数据。重复导入只重新核对，不重放资产。原文件实体、摘要及规范化内容也逐条核对；SQLite 原二进制另行保存在受控备份中。

覆盖范围包括兼容密码、管理员 TOTP（旧 Hex 密钥转换为相同字节的 Base32，再按目标新账号 ID 加密）、账号创建时间、金币与资产开账账本、库存分类、独立装备实例、钓竿槽位、图鉴、好友、商城周期、船只和任务进度、自动出售、订阅、开箱保底、市场托管、运营配置、价格覆盖及经济历史、反馈与管理审计、统计、纪录投影、历史资产快照、Wiki 内容和修订。

历史价格/交易记录进入独立只读历史表，不重新发放金币或物品。旧纪录投影与新渔获合并展示，不伪造原系统从未保存的完整渔获流水。已删除账号的历史快照和冷却元数据独立保存，不重新创建可登录账号。旧会话失效，运行内存中的编队不复活；有效钓点只建立无连接租约的暂停状态，本人重新登录建连后才从新的未来时间开始钓鱼，不补发离线收益。已失效钓点和已知显示缓存保留原文档案。

导入以目标版本内置目录为基础叠加旧服配置，保留 v0.21.5 的远征、套装和旧装备定义。潮汐砂、龙鳞在目标版本属于远征专属材料，生效商城不再展示这两项旧商品；旧商城原配置仍保存在来源档案，玩家既有库存和购买计数完整保留。材料禁售不影响查询已导入的价格与交易历史。既有自动出售规则照原样导入；禁售材料不参与预览或实际出售，用户可以关闭、删除其旧规则，不能新建或重新启用，其他物品的设置正常保存。

切换顺序：完整候选导入与对账 → 备份恢复到第二个隔离库并再次对账 → 目标运行角色权限验证 → 克隆库业务冒烟 → 备份现有线上数据库和配置 → 停止目标实例及其依赖网页服务 → 同时切换程序和数据库连接 → 启动后端与网页服务 → 检查公网、运行版本和数据摘要。原数据库及原发行目录保留。新服务开始接收玩家写入后，不能直接回退到旧数据库而丢弃新增数据。

SQL `0030_legacy_economy_history.sql` 必须通过候选库和恢复演练后部署；自动发布的 schema 摘要门禁不能绕过。运行用户仅获历史表 SELECT 权限，不能读取迁移原始实体或写迁移账本。重新设置自动发布基线时必须来自实际部署提交和已验证的 schema。
