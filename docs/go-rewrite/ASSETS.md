# 资产核心：金币、库存、装备与钓竿

历史说明：下文为 2026-09-20 schema 0001–0003 批次的设计与工作树验证范围，“尚未实现”和迁移延期不是当前状态。最新基线见 [DELIVERY.md](DELIVERY.md)，本轮迁移工具与合成演练按 [PARALLEL_ACCEPTANCE.md](PARALLEL_ACCEPTANCE.md) 推进。

当前提供内部资产用例：金币转账、奖励/制作/消耗、资产包交换，以及钓竿装卸/保存/切换，并为钓鱼周期和市集原型提供同事务接口。调用方必须先完成可信身份、玩法权限、规则和随机结果解析；这些方法不能直接绑定客户端提交的资产增减。当前没有公开玩法 HTTP 接口，尚未实现完整市场或双人交易协议。

## 数据所有权与不变量

| 表 | 所有者及用途 |
|---|---|
| accounts | identity 预留账号 ID；无凭据/注册实现，测试由专用种子创建 |
| player_state | assets 玩家守卫行、assets_rev、装配 loadout_rev、已购钓竿容量 rod_capacity（1～8） |
| wallets | assets 金币余额，0～9007199254740991 整数 |
| item_definitions | catalog 最小物品字典，分鱼/材料/宝匣/装备；当前由合成测试种子填充，assets 只读 |
| inventory_stacks | assets 按玩家、物品、体型分行的库存；材料/宝匣只能为 normal |
| equipment_instances | assets 独立实例 ID、所有者、定义/部位、完整属性及 available/consumed/escrow 状态 |
| rod_loadouts / rod_components | assets 钓竿槽位及实例绑定；活动保存槽只是同一组绑定的指针 |
| command_results | assets 主体＋请求号去重、规范输入摘要及原始结果 |
| asset_operations | assets 业务操作、规则版本与时间；同一请求唯一 |
| asset_entries / inventory_entries | 金币/库存增减及变更后的余额/数量 |
| equipment_entries / rod_entries | 装备创建/转移/消耗记录；钓竿变更前后快照 |
| outbox_events | 与操作共同提交的事件；当前只保存，不投递 |

业务表在 fishing schema，结构账本在 public.fishing_schema_migrations。账号、装备、操作 ID 用 bigint，序列化 ID 用字符串；金币、数量不超过 JS 安全整数上限。

鱼的 normal、large、giant 是互斥分类。旧 total 对应三档之和，bigfish.L/G 对应后两档，每条鱼只计一次；普通消耗不能动用大型/巨型库存。服务检查同物品三档最终总量上限，允许同事务改档。每行范围和非鱼体型由数据库约束保护；跨行总量依赖玩家守卫和资产服务，不宣称任意直接 SQL 都自动校验。

同属性装备的每份副本也有独立实例 ID，旧属性编码不能作为全局主键。转移保持实例 ID/属性，消耗保留 consumed 墓碑；市集托管设为 escrow，直到购买/返还原子解除占用。创建属性为最多 32 KiB、深度不超过 32 的 JSON 对象；规范化键顺序，不做 float64 往返转换，拒绝重复键、非法 UTF-8、未配对 Unicode 代理项、NUL 和超范围数值。JSONB 不保留原文空格/键顺序，此层不解释或重新计算词条。

一个装备实例最多绑定一处。复合外键要求绑定所有者、部位和 available 状态与实例一致；直接改写已绑定实例的所有者/消耗状态也会失败。活动保存槽不会额外复制一套装备。

## 用例与事务边界

| 内部方法 | 输入及行为 |
|---|---|
| TransferCoins | 主体、收款方、正金额及请求号；双方流水配平，返回原始双方余额 |
| ApplyChange | 可信服务端 Change 计划：reward/craft/consume、规则版本、金币/堆叠增减、创建属性和消耗实例 |
| ExchangeAssets | 双方、金币/堆叠及实例列表；正金币/数量为主体给对方，负值反向；装备列表单向由主体给对方 |
| ChangeRod | equip/save/use/stow/delete/rename，检查部位、所有权、绑定及容量 |
| Lookup | 按可信主体和请求号查询原始结果，适用于全部命令 |

请求号为 1～128 位字母/数字/点/冒号/下划线/连字符，后台专用前缀 fishing:settle: / market:expire: 禁止普通命令占用。堆叠项、创建项、消耗或转移实例列表各最多 100 项；重复堆叠键/实例 ID 拒绝。列表复制和排序后参与摘要，创建列表保留顺序以对应返回实例 ID。reward 仅增加、consume 仅减少，craft 可组合来源与去向；配方、费用和掉落概率由未来玩法用例负责。

四个写方法共用私有命令执行器和 assetTx：

1. 开启 READ COMMITTED 事务，以主体＋请求号创建/锁定命令记录。
2. 对比规范输入摘要；相同键/输入返回原结果，不同命令或输入复用同键则拒绝。
3. 按账号 ID 升序锁定 player_state，不得持有较大 ID 后追加较小 ID。
4. 在 asset_effects 保存点内创建操作，重验余额/库存/所有权并执行整个计划及流水。
5. 业务拒绝回滚到保存点，只持久保存拒绝结果；成功则递增参与玩家 assets_rev，写 outbox 和命令结果。
6. PostgreSQL 提交成功后才返回成功。

同事务已能组合金币、库存、装备效果。新增 Service.Run / Transaction 将市集挂单和钓鱼周期进度与资产一起提交，SQL 包装只提供查询/执行，不提供 Commit/Rollback，且资产方法校验玩家已在锁集中。未来双人报价等也必须使用这一边界；不能先独立提交资产再改业务状态，或嵌套调用 Service 形成两个事务。具体用例见 [PROTOTYPE.md](PROTOTYPE.md)。

所有资产写入口遵守玩家守卫锁。命令锁先于玩家锁，实例锁在玩家锁之后；未来经济/挂单资源锁次序需在对应用例中统一。不存在账号 ID 的调用不是有效身份，不能将存储错误当注册入口。

## 钓竿行为

- -1 表示未保存的活动装配；保存槽为 0～7，实际范围受 rod_capacity 限制。一个玩家最多一个活动槽。
- equip 校验部位/实例；重复安装同实例不重复消耗；替换解除原实例绑定。其他槽已绑定的装备拒绝安装。
- save 把未保存装配的绑定移动到保存槽；占用目标必须显式 Force。覆盖只解除旧绑定，装备仍归玩家。已激活保存槽不能另存复制到其他槽。
- use 切换保存槽，原保存槽保留绑定；原活动装配若未保存则解除绑定，部件重新可用。
- stow 收起保存槽时保留绑定，激活空的未保存装配；收起未保存装配则解除其绑定。
- 从活动保存槽卸一件会解散保存槽：余下部件移到未保存活动装配，卸下部件恢复可用。delete 解除整个保存槽绑定；rename 只改名称。
- 名称按 JS UTF-16 长度限制 20；槽位购买费用/扩容、整竿交易尚未接入。

这些语义依据 v0.21.4 的 bd 接口实现核对；未声明旧 HTTP 响应、错误文本、自动配装或前端完整兼容。

## 失败、重试与兼容

- 余额/数量不足、容量超限、装备不可用/已绑定等是持久业务结果。之后资产变化不会让同一被拒请求突然执行；新业务尝试需新键。
- 流水或 outbox 等技术故障回滚资产、绑定、版本、操作及结果全部变更，同键可重试。
- 周期未到期、周期容量不足或自动到期返还容量不足使用 ErrDeferred，全回滚且不保存终局结果，后台保持同一候选键重试；不能套用普通业务拒绝的永久结果缓存。
- 仅 PostgreSQL 明确返回的 40P01 / 40001 重试整个事务，最多三次、总时限 5 秒，复用相同输入与随机结果。
- COMMIT 不确定错误返回 ErrCommitUnknown。通过 Lookup 或同键/输入重试，不可生成新键再次扣款。Lookup 未找到可能表示旧请求仍在提交，不能证明失败。
- 保持 coin-transfer-v1 摘要、结果和 coins_transferred 事件字段兼容。新增命令有各自版本摘要，使用 assets_changed 事件。双方余额字段只用于金币转账，其他命令的零值不是实时余额。
- 尚无命令键、流水、outbox 清理策略；事件消费、修订号恢复及空间治理留待后续实现。
- 驱动错误不透传至 API/日志。事务、配平和完整审计由服务协议及对账保证，不等于任意直接 SQL 都安全。

## 数据库结构版本

0001_asset_core.sql 和 0002_inventory_equipment.sql 保持已提交内容不变，本批追加 0003_gameplay_prototype.sql，保留金币、分类库存、装备属性及钓竿绑定。cmd/migrate up 使用独立 FISHING_GO_MIGRATION_DATABASE_URL；这是新 Go 数据库 DDL 升级，和用户延期的旧服存档迁移无关。

嵌入 SQL 按编号排序，在事务级 advisory lock 下检查历史摘要、执行 SQL 并写账本，失败整体回滚。未知版本、缺口或摘要变化拒绝继续。game 只检查兼容性，启动与 readyz 要求三个版本完整匹配，不自动执行 DDL；账本检查不能发现全部手工改表漂移。

测试应用为随机受限登录角色：catalog/账号/结构账本只读，守卫/钱包查询更新，命令查询插入更新，库存/实例/槽位查询插入更新，绑定行另允许删除，流水/outbox 仅查询插入，序列 USAGE。禁止 DDL、删除流水和切换管理员角色。正式角色开通及发布配置留待部署阶段。

原型另授予 fishing_rules 只读，连接/会话/挂单查询插入更新，周期结算查询插入权限；完整服务测试使用相同受限角色验证运行。
