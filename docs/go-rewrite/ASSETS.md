# 资产核心首批：金币转账

本批仅交付内部资产用例，不新增游戏玩家转账功能。认证、双人交易确认、手续费、市场定价等业务尚未接入；不能把当前测试接口当成正式交易规则。

## 数据所有权

| 表 | 所有者及用途 |
|---|---|
| accounts | identity 预留内部账号 ID；本批无凭据/注册实现，测试由专用种子创建 |
| player_state | assets 玩家守卫行及 assets_rev |
| wallets | assets 金币余额，0～9007199254740991 整数 |
| command_results | assets 主体＋请求号去重，输入摘要及原始结果 |
| asset_operations | assets 业务操作、规则版本与时间；关联同一请求唯一 |
| asset_entries | assets 每方增减及变更后余额；当前转账恰好两笔、增量配平 |
| outbox_events | assets 与操作共同提交的通知记录；本批只持久保存，不投递 |

所有表在 fishing schema；结构版本账本在 public.fishing_schema_migrations。内部账号与操作 ID 使用 bigint；序列化 ID 用字符串，金币上限保持 JS 安全整数范围。库存/装备/钓鱼表将在对应用例中增加。

## 用例与事务边界

应用层在身份与权限校验后调用 `assets.Service.TransferCoins`，ActorID 必须来自可信身份上下文。服务接受主体、收款方、金额、请求号；禁止同人转账、非正金额、溢出和非法请求号。请求号允许 1～128 位字母/数字/点/冒号/下划线/连字符。

本用例拥有完整事务。未来市场等多模块用例需要由顶层应用用例持有同一事务并调用资产事务接口，不能在市场事务里嵌套调用当前独立转账服务。

1. 开启 READ COMMITTED 事务，以主体＋请求号创建/锁定命令记录。
2. 对比规范输入摘要。相同请求返回原始结果；相同键但金额/收款方不同则拒绝。
3. 按内部账号 ID 升序逐个锁定 player_state；不得在持有较大 ID 后追加较小 ID。
4. 锁内检查钱包余额及收款方上限，更新双方钱包与 assets_rev。
5. 写业务操作、借贷两笔流水、outbox、完整命令结果。
6. PostgreSQL 提交成功后才返回成功。

所有资产写入口必须遵守玩家守卫锁；这里不允许其他业务绕过 assets 直接改 wallets。命令锁先于玩家锁；未来调用链必须统一此顺序。当前无经济/挂单资源锁，增加时再固化对应次序。

余额不足、收款方不存在、收款余额超限是持久化业务结果；之后余额变化也不会让同一被拒请求突然执行。修改后的业务请求必须换新键。认证前不存在的 ActorID 不属于有效资产调用，目前返回存储不可用，不实现注册/账号修复。

## 失败、重试与查询

- 仅 PostgreSQL 明确返回的死锁 40P01 / 序列化中止 40001 可重试整个事务，最多三次，复用相同输入和键；请求总时限 5 秒。
- 写流水或 outbox 失败时回滚钱包、版本、操作、结果和事件全部变更。
- COMMIT 返回不确定错误时返回 ErrCommitUnknown。通过 `Lookup(actor,key)` 查询或以相同键/输入重试，不能生成新键再次扣款。
- Lookup 的结果属于原始操作，不是实时钱包余额。未找到结果可能表示旧请求仍在提交，不证明失败。
- 未设置清理/过期策略；目前命令键、流水和未投递 outbox 都保留。未实现对旧键的归档与空间治理。
- 驱动错误不透传至 API/日志；对外只有固定错误类别。日志、请求摘要不包含密码/凭据。

数据库约束阻止负余额与范围溢出；多表配平由事务服务与测试对账保证，不能宣称任意直接 SQL 都会被数据库自动校验配平。

## 数据库结构版本

`cmd/migrate up` 使用单独的 FISHING_GO_MIGRATION_DATABASE_URL；这是新 Go 数据库的 DDL 升级，不是旧服存档导入。嵌入 SQL 按编号排序，在同一事务级 advisory lock 下检查历史摘要、执行待应用 SQL 并写账本，失败整体回滚。已发布 SQL 不修改，只追加版本；未知版本、缺口或摘要变化拒绝继续。

game 使用应用账号，只检查兼容性，不执行 DDL。启动与 readyz 均要求结构版本完整匹配；发现不匹配拒绝就绪。当前检查确认版本账本，不能发现绕过升级流程手工改表导致的所有漂移。

本批测试账号只有 schema USAGE、账号只读、钱包/守卫查询更新、命令查询插入更新、流水/outbox 查询插入、序列 USAGE 和结构账本只读权限。禁止 DDL、删除流水和切换管理员角色。生产账号开通、身份表写权限及发布配置尚待部署阶段实现。

## 验证范围

真实 PostgreSQL 测试使用自动生成的独立数据库及随机受限登录账号；每轮销毁自己的数据库、角色和容器。不挂载真实存档。覆盖并发重放、冲突请求、双向转账锁序、并发超支、持久业务拒绝、金额上限、孤立收款方、outbox 故障回滚、锁等待取消后同键重试，以及余额/流水/版本/outbox 对账。测试通过触发器注入 40001/40P01，验证整个命令重试及三次上限；这不等于已覆盖所有真实死锁拓扑。

结构升级测试覆盖四路并发执行、重复执行、历史摘要篡改拒绝、DDL 失败回滚和 schema 变化导致未就绪。现有连接池集成测试也纳入同一轮。

尚未通过网络代理注入 COMMIT 回包丢失、数据库崩溃/主机断电或磁盘故障；也未完成长期容量压测、资产审计页面、outbox 消费者和多机验证。代码中的结果查询及错误分类不能代替这些故障验收。
