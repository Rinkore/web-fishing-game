# 钓鱼周期与市集交易原型

本批将持久钓鱼周期、市集挂单状态与已有资产事务接通，并在 `all` 服务中启动调度和到期返还。使用合成规则验证事务路线；不是 v0.21.4 完整玩法替代，也不是正式数据迁移或性能放行。

## 代码入口与运行

| 入口 | 能力 |
|---|---|
| assets.Service.Run / Transaction | 统一命令幂等、玩家锁、保存点、资产效果、事件及提交；参与模块只能使用当前事务 |
| fishing.Service.Connection | 可信网关建连、心跳、断线；连接代次阻止旧断线回调关闭新连接 |
| fishing.Service.Start / Stop | 选择不可变规则版本、创建/重置持久会话、主动停止 |
| fishing.Service.Settle / Sweep | 按指定会话/代次/序号结算一个周期；有界扫描及执行 |
| market.Service.List / Buy / Close | 上架托管、整份购买、撤回/到期返还 |
| market.Service.Open / Expire | 游标分页读取开放挂单、扫描到期挂单 |
| app.Run | 基础 HTTP + 钓鱼调度器 + 市集到期任务；取消后等待任务退出再关闭连接池 |

按 [server-go/README.md](../../server-go/README.md) 升级独立开发库并启动 `cmd/game --role=all`。当前仍只开放 healthz/readyz，未注册玩法 HTTP/SSE、身份认证或无鉴权测试接口。测试通过内部方法创建合成账号、连接、会话和挂单；普通启动不自动填充规则或生成玩家资产。就绪探针仍只声明 infrastructure。

## 事务和失败语义

玩家状态、钓鱼进度、挂单状态的所有写入先通过统一命令边界。顺序为命令记录 → 玩家守卫（账号升序）→ 业务资源 → 资产子行。市集买入先非锁定读取不可变卖家 ID 以确定双方锁集，锁后重读挂单并验证状态、价格与到期时间。到期时间在取得资源锁后按数据库时钟判断。

`Transaction.SQL()` 提供查询/执行能力，不暴露 pgx 事务或 Commit/Rollback；参与模块不打开第二个事务、不调用外部网络、不保留事务对象。资产子表仍由 assets 方法写入，Coins/Stacks/装备托管方法验证相关玩家已在声明的锁集中。同一操作对同一钱包/库存行写一次流水；未来更复杂业务需要先合并净增减，不能反复调用造成重复流水键。

资产与业务状态、流水、outbox、命令结果在同一个提交中完成。业务拒绝只保存稳定结果，已经扣除的部分资产回滚。技术故障全回滚，同键可重试；已有金币命令摘要和事件契约保持兼容。

新增 `ErrDeferred` 表示尚不能执行且不保存终局结果，防止后台固定业务键被永久拒绝污染。适用：周期未到期、周期奖励超过容量、挂单尚未到期、自动返还超过背包容量。后台保留同一候选和键，容量恢复后重试。用户主动购买/撤回的业务拒绝保持原结果，新尝试需新键。

`fishing:settle:` 和 `market:expire:` 是后台专用请求号前缀，普通资产、装配、连接、上架等命令不能使用。到期命令还需绑定相应挂单 ID 和 Expire 语义；普通撤回不能占用到期键。此规则阻止其他命令提前抢占自动任务的去重记录。Lookup 仍可按可信主体查询这些后台结果。

COMMIT 结果不确定仍返回 ErrCommitUnknown，只能查询或同键重试；原型未注入网络回包丢失。对外错误和后台日志不输出 SQL 详情、连接串或私有种子。

## 钓鱼周期

`fishing_sessions` 每玩家一行，含独立 ID、generation、next_seq、连接代次、状态、到期时间、规则版本、装配修订号、自动出售选择及私有随机种子。重新开始递增 generation 并将 next_seq 重置为 1；旧候选不能替换成最新序号继续发奖。

结算锁内检查 active、连接有效期/代次、预期 generation/seq、装配修订号和到期时间。写收益或空竿结果后，在同一事务推进 next_seq、下一到期时间和资产修订号。`fishing_settlements(session_id,generation,seq)` 唯一约束是额外防线；空竿同样记结果和推进，不能重抽。

开始时由 crypto/rand 生成 32 字节私有种子，重试复用；客户端不能提供种子。采用 HMAC-SHA256，域为 `fishing-hmac-sha256-v1:bite:`，输入为四个大端 uint64：session、generation、seq、拒绝采样计数器。无偏映射到 0～999999，按 bite_ppm 判定。版本随会话/结算记录保存；有独立 Node crypto 固定向量测试。种子不进入请求摘要、返回结果或事件。原型中种子存于受限数据库列，正式启用前仍需完善密钥/种子加密、访问隔离及恢复方案。

连接原型采用 15 秒数据库有效期。可信网关需定期 heartbeat；过期后必须重新 connect，不能用旧心跳复活连接。disconnect 或新连接接管暂停原会话并使其旧代次失效；恢复调用 Start 重新计时。进程停止期间不按旧 due_at 循环补发，下一周期从当前数据库时间加间隔；若租约仍有效，可结算一个已经到期的候选，过期则暂停。

ChangeRod 与结算共用玩家锁并递增 loadout_rev。调度发现版本不同就递增周期代次、重置计时，本次不发奖；停止先提交则旧周期失效，结算先提交则该周期有效。目前包括改名/非活动槽变更在内的所有 ChangeRod 都触发重排，且由调度检测时开始新间隔；完整 v0.21.4 换装即时重启、自动续钓、顶号/多标签页宽限仍待对照接入。

`fishing_rules` 是不可变、显式命名版本的最小测试 catalog：100～60000ms 间隔、每百万上钩概率、单一鱼种/体型、1～100 数量和固定售出单价。数据库检查鱼种类型并禁止修改已发布行。AutoSell 仅对 normal 且价格非零的收获生效，直接记售出数量与金币；大型/巨型进入对应库存，保持预留分类。尚无正式 catalog 导入/发布、装备效率、权重掉落、多钓公式、供需、税费或图鉴奖励，不能把测试价格当正式经济规则。

## 调度与恢复

原型采用等效的数据库扫描调度，未加内存优先队列/租约认领层。每 100ms 最多扫描 64 个到期候选，最多 4 个并发执行者；所有扫描不持资源锁。Sweep 参数限制为最多 100 候选/8 个执行者。查询/命令有超时，取消会停止派发并等待当前任务回滚或完成。

扫描游标按 due_at、ID 前进，扫到末尾归零；永久满背包不会一直占据首批而饿死后续玩家。进程重启从持久表重建候选，重复执行依靠代次/序号/唯一键保护。市集到期任务每秒扫描最多 64 条，单批最多 5 秒，按 ID 游标轮转；返还失败保留托管状态。错误日志每个任务最多每 5 秒一条，不输出原始驱动错误。

这些参数是有界原型配置，不是 100/1000/5000 人容量承诺。批次统计表示本次返回成功/推迟/失败的候选数，重放也可能返回成功，不能据此统计唯一新增竿数。当前每次连接命令、空竿及其他成功操作都会生成操作/结果/outbox 并递增 assets_rev；高频成本、保留/压缩策略、SQL 次数、锁等待和 WAL/磁盘测量需另行验收。

## 市集交易

一个挂单是一份不可拆分的库存包或一件装备，总价固定。上架减少可用库存，挂单 open 状态承载该份托管数量；装备则变为 escrow 并绑定 escrow_listing_id，保留原所有者及属性，不能继续装配/转移/消耗。卖家、资产、总价和有效期发布后不可改，终局状态不可重新打开。

购买锁定买卖双方及挂单，重验 ExpectedPrice、open、未到期，再原子扣买家金币、加卖家金币、释放库存/装备给买家并置 sold。撤回/到期释放给卖家，置 cancelled/expired。只有一个终局转换成功；两个买家抢最后一份或买入与撤单竞争均不能重复取得资产。托管返回遇到容量上限不会丢弃资产。

持有库存加 open 挂单数量才是该物品的完整存量，不能把上架流水当系统销毁；装备完整存量包括 available、escrow 和 consumed 墓碑，当前可用量只含 available 且未绑定的实例。测试核对逐账号余额/库存流水、装备托管对应、绑定归属及操作事件完整性。

Open 使用稳定 ID 游标，每页最多 100 条，只展示 open 且未到期挂单；展示后状态可变化，购买必须重验。未实现部分成交、整竿买卖、手续费、挂牌费、报价修改、双人邀请/双方确认交易或旧市集协议。
